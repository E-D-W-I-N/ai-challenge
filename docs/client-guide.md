# Карта клиента дня 25

FastAPI отдаёт HTML, CSS и пять обычных локальных скриптов; сборки нет.
`index.html` загружает `text.js` → `records.js` → `models.js` → `rag.js` → `app.js`.

| Файл | Граница |
|---|---|
| `app/static/text.js` | Чистые Markdown/экранирование, формат чисел, stop/JSON, сравнение значений, предупреждения параметров. В браузере `ChatText`, под Node объект CommonJS. |
| `app/static/records.js` | `createChatRecords({state, $, el, iconButton, api, json, fmt})`: память, общий editor, профиль, инварианты, ленивый MCP. State один, передаётся из app.js; запросов при создании фабрики нет. |
| `app/static/models.js` | Общий поисковый provider/model компонент и каталог для чата, подготовки, разбиения, эмбеддингов и ранжирования. Общий URL сервера; ключи остаются на сервере. |
| `app/static/rag.js` | `createRagInspector`: durable stages UI/CLI, pages документов/чанков до публикации, lazy vector; исторический снимок ответа без чтения текущего индекса. |
| `app/static/app.js` | State и DOM/API-помощники, список чатов/ветки, лента/поток/промпт/метрики, команды задачи, настройки, sidebar/подтверждения и init. Фабрика возвращает только функции/карты, нужные этой оболочке. |
| `app/static/style.css`, `index.html` | Светлая гибкая оболочка для ноутбука: sidebar, общая шапка, области настроек приложения/чата, метрики разговора. Компактные формы без отдельного phone/drawer режима. |

В Node `require(app/static/app.js)` подключает соседние модули и отдаёт
`init`, `state`, `renderMarkdown`, `readStopLines`, `parseCommand`,
`parseResponseFormat`, `paramWarnings`, `fmt`. Init вызывает стенд после
установки DOM/fetch. В браузере app.js вызывает init сам.

Проверки находятся в `checks/browser_check.js` (настоящий клиент),
`checks/dom.js` (DOM), `checks/fixtures.js` (сценарные API/SSE), `checks/run_checks.py`
и отдельных restart/two_processes/MCP-фикстурах. `make check` — всё ядро,
`make check-browser` — только Node. Стенд не реализует второй сервер:
ожидаемые промпт, суммы и переходы проверяются независимо на Python.
HTML-путь исполняет настоящие скрипты из разметки по порядку без CommonJS,
дополняя `require(app.js)`. Матрицы оформления, проверки CDN/слов в исходниках,
batch-100 и длинные серии 25/500 обменов больше не являются автоматическим
обещанием; короткие различающие случаи, small isolation/deep-copy
и межпроцессное владение остаются проверяемыми границами.

## Ручной прогон

Используйте offline API-фикстуры/временную базу или подготовленное демо.
Не обращайтесь к пользовательской базе, `.env` или живой LLM.

1. Откройте desktop 1440 px, ноутбук 1100/900 px и окно с zoom 125–150%.
   Кнопкой с гаечным ключом в шапке откройте «Настройки приложения»: Модели, Память, Профиль,
   Инварианты, Инструменты, Индекс RAG. По шестерёнке рядом с карандашом
   в строке чата откройте его настройки: Модель, Агент, Память, условные Напоминания,
   Поиск RAG. Формы доступны при прокрутке, длинные слова
   переносятся, код/JSON и нижняя строка метрик прокручиваются внутри области.
   В Network проверьте, что скрипты/CSS и остальные ресурсы локальны,
   нет CDN, сетевых шрифтов и библиотек.
2. Сверните/откройте список: видна одна кнопка, фокус переходит к ней,
   скрытый список не участвует в Tab, предпочтение переживает перезагрузку.
   Проверьте центры SVG, строки текста, шапку дня и baseline метрик/заметок.
3. Прямой кнопкой откройте настройки приложения и редактор «Профиль». Проверьте черновик/ошибку после смены областей,
   подписи full/window/summary, guard без метрик, пустой/down MCP и
   напоминания и кнопку «Снять» для задачи текущего чата. Оставьте вкладку открытой
   для обновления через 2 секунды; скрытие/уход останавливает опрос,
   повторный вход сразу обновляет, раскрытая схема сохраняется. В чате
   проверьте удачный/ошибочный tool-бейдж до конца потока и после открытия
   чата; нижние шесть метрик стабильны. Для pipeline проверьте три последовательных
   бейджа search/summarize/save_file с именем сервера до done и после открытия;
   длинные описания и раскрытые схемы не расширяют страницу. Подключите отдельно
   запущенный pipeline по URL и проверьте четыре сохранённых JSON-раунда ответа
   после refresh; настройки и paths выбираются в приложении и сервисе соответственно.
   Для нескольких серверов проверьте порядок git_log · git → ping · echo до done
   и после открытия, сохраняя отдельную строку из шести метрик.
4. Один editor: смените текст/тип, Enter, focusout, Escape, пустую/неизменную
   правку. Одно подтверждение: Tab, Escape и возврат фокуса; стрелки/Home/End
   на вкладках, видимый outline и prefers-reduced-motion.

Это проверка представления; она не заменяет автоматические границы хранения,
payload, идентификаторов, отмены позднего GET и асинхронных гонок.

Для scheduler оставьте исходный чат открытым, не открывая «Напоминания»: после
срока должен появиться новый подписанный результат и реальные tool-бейджи.
Проверьте два повтора, сохранение черновика/незаписанных настроек и переключение
чата во время GET; скрытие окна прекращает poll, возвращение сразу обновляет.

## Ручной просмотр индекса

С явным `--root` в отдельном временном каталоге запустите CLI ingest/index с offline HTTP-фикстурой
или просматривайте явно подготовленный оператором снимок без вызовов модели.
Кнопкой с гаечным ключом в шапке откройте «Настройки приложения → Индекс RAG» без выбранного чата и ключа. Проверьте стадии
реальной CLI-операции и счётчики, затем сохранённую SQLite/объём/размерность;
выберите документ и чанк, сопоставьте его границы с очищенным текстом и раскройте
числовой вектор. Перезагрузите страницу после завершения — тот же index_id
и данные должны читаться из SQLite. Ошибка новой операции должна быть видна
рядом с прежним индексом; после остановки процесса running становится interrupted.
Проверьте длинный source/chunk_id/vector и широкую страницу на 900/1100/1440 px.
Смена вкладки/скрытие окна прекращает poll и поздний ответ не рисует скрытую страницу.

UI workflow: статус операции и навигация этапов остаются над текущей формой.
Кнопки «Документы / Чанки / Эмбеддинги / Индекс» выбирают один этап; текущий
выбор и выполняющийся этап отмечаются независимо. Доступность берётся из
валидных снимков corpus → chunks → vectors, а опубликованный индекс остаётся
доступен для просмотра. Poll сохраняет формы, draft, focus, выбор и details.

1. На этапе документов задайте явные URL или настроенный HTML manifest.
   Подготовка «Кодом» по умолчанию не показывает настройки модели. Включите
   «Полностью через LLM»: появляется общий выбор провайдера и модели, тайм-аут.
   Проверьте очищенный документ и фактический отчёт подготовки, токены и USD.
2. На этапе чанков выберите размер и способ разбиения. Семантическое разбиение
   открывает тот же компонент модели; его выбор независим от подготовки.
   Дополнительные параметры раскрываются отдельно. Просмотрите результат до
   эмбеддингов; полные тексты выбранных документа/чанка доступны при прокрутке.
3. Эмбеддинги используют тот же provider/model компонент с embedding-каталогом.
   Размерность и ревизия находятся в дополнительных параметрах. Пустой ID
   блокирует создание, точный введённый ID передаётся без изменения namespace.
   Создание сохраняет векторы; публикация индекса остаётся отдельной операцией.
4. На этапе индекса сопоставьте реальные документы, чанки и ленивый вектор
   сохранённой SQLite. После изменения корпуса это данные прежнего индекса.
   Удаление индекса сохраняет предыдущие этапы, повторное сохранение не вызывает
   модель. Удаление эмбеддингов сохраняет документы/чанки; удаление чанков —
   документы. Проверьте инвалидированные downstream этапы и сохранение выбора.

## Общий выбор моделей

«Модель» в настройках чата показывает его провайдера, модель и параметры
генерации. «Модели» в настройках приложения содержит единственный URL
OpenAI-совместимого сервера. URL доступен без выбранного чата.
Ключ задаётся в серверном окружении и в браузер не передаётся. OpenRouter и
OpenAI-совместимый сервер доступны в каждом сценарии. Один компонент содержит
провайдера, поисковое поле модели с каталогом и кнопку обновления; допускает
точный ручной ID. Уточнение запроса использует модель и провайдера чата.

Во всех пяти селекторах есть «Рассуждения (если модель поддерживает)», включая
эмбеддинги и неизвестные модели. Новые/legacy значения OFF. Включите его в
чанкинге: чат, подготовка, реранкинг и эмбеддинги сохраняют собственные значения.
Переключите провайдера, обновите каталог и дождитесь status poll: локальный
выбор не сбрасывается. Перезагрузка восстанавливает сохранённые stage configs;
чат сохраняет переключатель через PATCH и fork. Embedding preference не меняет
стандартный HTTP запрос или fingerprint индекса. Для генерации сравните actual
JSON OFF/ON; неподдерживаемый режим даёт ошибку, без автоматического повтора.

Проверьте смену провайдера и возврат: свой ID каждого варианта сохраняется.
Во время запроса каталога измените ID; ответ не затирает выбор. При loading,
error и пустом каталоге сохраняется точный ID и показывается фактическое
состояние; нет guessed prefix aliases, подмены модели или выдуманных цен.
Каталог обновляется при открытии соответствующего этапа, смене провайдера,
общего URL или вручную; status poll не повторяет каталог. Поздний ответ
прежнего провайдера/URL/скрытого этапа не меняет текущий выбор. Проверьте два
последовательных сохранения URL и новую незаписанную правку во время PATCH:
она остаётся в поле. Изменение только адреса сервера не меняет модель индекса;
выбор другой embedding-модели применяется при явной перестройке.


Области используют одни смонтированные формы: возврат «Вернуться в чат»
сохраняет черновик сообщения, системного промпта, рабочей/долговременной памяти
и параметры этапов. Повторная шестерёнка текущего чата не перечитывает чат и
не прерывает поток. Шестерёнка другой строки открывает именно этот чат; поздний
GET не отменяет более новое открытие настроек приложения или соседнего чата. Стрелки
клавиатуры проходят только видимые вкладки выбранной области. Глобальные формы
доступны при пустом списке, без создания чата и без PATCH его конфига.

Память приложения читает `/api/memory` и показывает только долговременные
записи. Память чата показывает краткосрочную и рабочую память. В глобальных
«Инструментах» доступны подключения MCP и общий каталог; GET не передаёт
`X-Chat-ID`. В чате раздел «Напоминания» виден только при подключённом
сервере с фактическим reminders/reminders_error, включая пустой список.
Каталога инструментов в чате нет. Снятие привязано к владельцу строки, старый callback не отправляет
отмену под новым чатом. Глобальная область не показывает напоминания текущего
чата. Заголовок задачи и метрики остаются в разговоре; guard/debug/JSON открываются
рядом с принадлежащим им ответом. Исторический RAG — отдельный read-only просмотр
без вкладок настроек; «К текущему индексу» открывает область приложения.

Проверьте вход в чат без reminder capability, подключение с пустым списком,
ошибку списка при живом сервере и отключение открытого раздела. Фокус/стрелки
переходят только к доступным вкладкам; поздний GET прежнего чата не добавляет
пункт. Discovery не запускает глобальный фоновой poll. Удаление последнего
чата создаёт один replacement; отказ DELETE оставляет старый чат, отказ
создания убирает его ленту/метрики и предлагает повторить «Новый чат».

## Ручной просмотр ответа с RAG

На neutral offline-фикстуре по шестерёнке чата откройте «Поиск RAG».
В этой области нет стадий индексации и опроса индекса. При RAG ON видны
независимые Rewrite/Reranking и два числа: «Кандидатов для поиска» (10),
«Чанков для ответа» (3). При OFF подробности скрываются, значения сохраняются.
Оба числа целые1..100; второй не может быть больше первого. Уменьшите только
кандидатное число ниже итогового: PATCH не отправляется, введённое остаётся
для исправления. Измените пару на допустимую и переключите чат: у каждого
свой конфиг, fork наследует оба значения. Reranking открывает общий selector
provider/model с отдельным выбором; модель Rewrite — текущая модель чата.

Порог cosine виден всегда при RAG ON и проверяет выбранный контекст,
не фильтруя кандидатов перед ранжированием.

Отправьте вопрос: реальные стадии Rewrite → Search → Reranking → Generation
показываются только когда выполняются. Поиск возвращает до K кандидатов;
реранкинг получает всех, в том числе низкий cosine, а первые N в новом порядке
поступают в контекст. При OFF ранжирования выбираются первые N по cosine.
Пустой поиск не вызывает финальную модель. Ошибка возвращает ввод и actual JSON
с доступными метриками, не добавляя обмен; regenerate восстанавливает прежний ответ.

При отсутствии выбранных фрагментов или их максимальном cosine ниже порога показывается
«Не знаю: в базе не найдена достаточно релевантная информация. Уточните вопрос.»
без финальной генерации и выдуманных источников/метрик модели, независимо от реранкинга.
После прохождения порога составной вопрос получает ответ на подтверждённые части
с указанием недостающих данных. Модельный JSON-отказ — ошибка формата. При
отказе поиска вопрос возвращается в ввод, обмен не добавляется; не должно
оставаться занятого состояния. Для regenerate прежний ответ восстанавливается.

У нового ответа ссылки [1], [2] ведут к карточкам источников под ответом.
Карточка показывает название, источник, раздел (или chunk_id) и цитату модели;
номера соответствуют сохранённым фрагментам, поэтому возможны пропуски.
Проверьте ссылки с кодом и длинные цитаты: Markdown и код сохраняются, источник с
опасной схемой URL остаётся текстом. Новая подпись — «Источники и цитаты»: дословность и смысловая поддержка не проверяются.
Исторический verified сохраняет прежнюю подпись «Цитаты проверены».
Переключите сырой текст и вернитесь: локальные ссылки снова ведут к карточкам.
Отказ и подтверждение напоминания не показывают карточки цитат. Legacy ответы
показывают прежние найденные фрагменты без приписанной проверки.
При ошибке проверки цитат ответ не публикуется, вопрос возвращается во ввод
(при regenerate восстанавливается прежний ответ); временная диагностика содержит
ошибку и actual JSON без автоматического платного повтора.

Откройте «Контекст и фрагменты ответа». Snapshot v3 показывает ВСЕХ кандидатов
в итоговом порядке: источник первым, «До → после» вторым (только actual rerank),
cosine третьим. Метка «В контексте» внутри источника отмечает выбранные первые N.
Проверьте продвижение хвостового низкого cosine в начало и доступность полного
текста оставшегося за лимитом кандидата: он не попал в точный контекст, но не исчез
из отчёта. При Reranking OFF нет модельных рангов/usage/diagnostics этапа.
Выбор строки показывает один полный сохранённый текст и его метаданные.
Контекст и фактический JSON полные, раскрываются отдельно; неизвестный usage
не заменяется нулём. Сведения Rewrite используют только сохранённый флаг.
Измените текущие переключатели: сохранённые сведения не меняются, настройки
применяются только к следующим ответам. Без выбранного чата карточка настроек
скрыта, этапы индексации доступны. Старый снимок дня 22 продолжает показывать сохранённые данные.
При ошибке переформулирования раскройте «Информация о неудачном запросе» под
полем ввода: там фактический JSON и доступные метрики вызова. Это временная
диагностика, она не добавляет упавший обмен в историю или итог чата. На 1100/1440 px длинные source/title и точный контекст
доступны на полной ширине; данные показываются как текст. Затем измените или
удалите текущий индекс: исторический снимок этого ответа остаётся прежним.
В Network открытие снимка не запрашивает status/documents/chunks/vector.
Проверьте поздний ответ current-index GET и возврат «К текущему индексу»:
снимок не заменяется, формы индексации остаются смонтированными с черновиками.


Старые v1/v2 snapshots читаются без переписывания. Проверьте v2 с исключённым
по порогу источником перед двумя переставленными hits: модельные ранги относятся
к этим сохранённым hits, исключённый источник остаётся без модельного ранга.
Старые причины threshold/final_cap и параметры видны только по saved filter flag.
Измените текущие настройки/индекс: исторический snapshot неизменен, его открытие
не делает GET status/documents/chunks/vector. Поздний current-index GET не меняет
историю. «К текущему индексу» возвращает mounted формы с draft/details.

selector; оформление оценивается вручную, offline поведение проверяется под Node.
