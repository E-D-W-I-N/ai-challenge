# Независимый pipeline MCP-сервис

Python >=3.11, установленный Git и собственный закреплённый MCP SDK.
Сервис не импортирует app/Agent/Store/LLM, не открывает базу чатов и не
использует ключ модели. Оператор явно выбирает Git-контекст через `--repo`
и единственный каталог результата через `--files-dir`.

Из корня проекта, в отдельном терминале:

```sh
python3.11 -m venv /private/tmp/pipeline-mcp-venv
/private/tmp/pipeline-mcp-venv/bin/python -m pip install -r services/pipeline/requirements.txt
/private/tmp/pipeline-mcp-venv/bin/python -m services.pipeline --repo /absolute/path/to/repository --files-dir /absolute/path/to/files --port 8019
```

В «Настройки → Инструменты» приложения добавьте любое имя и URL
`http://127.0.0.1:8019/mcp`, сохраните и подключите. Disconnect/shutdown
приложения оставляет процесс живым; остановка сервиса — Ctrl+C в его терминале.
`--host` по умолчанию `127.0.0.1`. Для явной stdio-фикстуры есть `--stdio`.

Инструменты сохраняют поведение дня 19:

- `search(query, limit=20)` — `git grep -n -i -F --untracked` в выбранном
  репозитории, сортировка по файлу и числовому номеру строки, затем top-N.
  Git-ignore применяется к новым файлам; каталог результата внутри репозитория
  должен быть в его `.gitignore` (в проекте `/files/` уже игнорируется).
- `summarize(text, max_items=10)` — механический дедуп строк, группы по файлам,
  явно названное ограничение числа групп. LLM внутри сервиса нет.
- `save_file(name, content)` — UTF-8 запись в выбранный каталог, включая
  перезапись существующего имени через атомарную замену записи каталога.
  Существующая символическая ссылка заменяется обычным файлом; её цель не меняется.
  Имя непустое, без краевых пробелов, `/`, `\`
  и `..`; отказ не создаёт каталог или файл.

Цепочку ведёт модель через обычные tool responses; сервис не передаёт результаты
между инструментами сам. Старый `app.mcp_servers.pipeline` — тонкий совместимый
alias для stdio-проверок с временным ROOT и `PIPELINE_FILES_DIR`; обычный HTTP
запуск использует только явные пути оператора.
