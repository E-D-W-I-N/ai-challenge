# Работа с day-17

Чат-клиент OpenRouter: FastAPI, SQLite стандартной библиотеки, ванильный JS
без сборки и внешних шрифтов, библиотек или иконок. Python >= 3.11; зависимости
и их версии заданы в `requirements.txt` (FastAPI, Uvicorn, HTTPX, MCP SDK).

Перед изменениями прочитайте относящиеся к задаче разделы
[docs/architecture.md](docs/architecture.md): это обязательные действующие
инварианты дня 17. Для промптов и агента — «Промпт и контекст», «Память и
профиль», «Задачи и инварианты», «MCP и инструменты»; для базы — «Хранение и
очистка», «Ветвление»; для клиента — также «Клиент»; для проверок — «Проверки».
При пересечении областей прочитайте каждый затронутый раздел.

## Безопасность

- Не читать, не выводить и не коммитить секреты: `.env`, `.env.local`, ключи,
  auth-файлы личных инструментов. Базы с текстами диалогов также не коммитить.
- Репозиторий публичный. Только `git add` с явным перечнем файлов;
  `git add .` и `git add -A` запрещены. Утечку нельзя отменить удалением коммита.
- Живых вызовов LLM не делать. Проверки используют `checks/_stub.py` и не
  требуют ключа. Для smoke запускайте с временной `AGENT_DB_PATH` и
  `MCP_DISABLED=1`; проверяйте health, не отправляйте сообщения модели.
- `mcp.json` — конфигурация MCP приложения, не OpenCode/Pi. Не смешивать
  ключи и настройки личных инструментов с настройками приложения.

## Команды из корня

```sh
make help
make setup                         # создаёт или использует .venv
make setup PYTHON=/path/to/python  # Python >= 3.11, только для создания .venv
make run                           # http://127.0.0.1:8000
make check                         # полный набор, включая subprocess и браузер
make check-browser                 # только клиент под Node.js
```

`PYTHON ?= python3.11` не меняет существующую `.venv`: run/check всегда
используют её Python. setup устанавливает requirements, не перезаписывает
`.env` и не пересоздаёт существующую среду. Node.js обязателен для check.

## Правила проверок

- Проверять наблюдаемое поведение, а не текст исходников или документации.
  Клиент проверять исполнением настоящего `app/static/app.js` в Node.js.
- Не добавлять мета-проверки, самопроверки стенда и таблицы запрещённых слов.
  Объём проверок держать меньше продукта, устраняя дублирование сценариев.
- Помощник готовит сцену без утверждений; измеряемые значения, число обменов,
  счётчики вызовов и сравнения оставлять в самой проверке. `_body_rules`
  возвращает нарушения, утверждает проверка. Для подмен — `patch.object` и
  `patch.dict`, без собственного помощника «подменить и вернуть».
- Различать слои значениями, специфичными для слоя; очистку проверять на
  непустых данных. Заглушка должна зависеть от проверяемого промпта;
  проверка ответа сопровождается проверкой самого промпта.
- После изменения запускайте подходящие поведенческие проверки и `make check`;
  сохраняйте ненулевые коды ошибок. Не фиксировать числа проверок в документации.
