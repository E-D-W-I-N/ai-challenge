# Работа с репозиторием

День 19: чат на FastAPI, ванильном JS и SQLite с MCP-пайплайном
`search → summarize → save_file`. Зависимости задаёт `requirements.txt`.

Перед изменениями **прочитайте соответствующие разделы
[docs/architecture.md](docs/architecture.md)** и сверьте поведение с исходниками:

- `app/agent.py`, `app/llm.py`, `app/schema.py`: промпт, контекст, память,
  состояние задачи, инварианты, цикл инструментов;
- `app/store.py`, `app/registry.py`, API: хранение, очистка, ветвление;
- `app/mcp.py`, `app/mcp_servers/`, `mcp.json`: MCP и пайплайн Дня 19;
- `app/static/`, `checks/`: интерфейс и поведенческие проверки.

## Безопасность

- Репозиторий публичный. Не читайте, не печатайте и не коммитьте секреты,
  `.env`, ключи, базы с диалогами и результаты в `files/`.
- **Никогда `git add -A` или `git add .`**: перечисляйте файлы явно,
  проверяйте staged diff перед коммитом.
- Не делайте живых вызовов LLM. Проверки используют `checks/_stub.py`
  без ключа; smoke выполняйте с временной базой и `MCP_DISABLED=1`.
- Не перезаписывайте пользовательские `.env` и `.venv`. Модель и авторизация
  OpenCode/Pi — личные настройки инструментов, не конфигурация приложения.

## Команды из корня

Нужны Python **не ниже 3.11**, Node.js и git; `make` выводит помощь.

```sh
make setup
make run
make check
make check-browser
```

`make setup PYTHON=/path/to/python` выбирает интерпретатор **только для
создания** `.venv`; существующее окружение используется повторно.
`make check` запускает весь набор, включая subprocess и браузерные проверки;
`make check-browser` нужен для отдельной проверки клиента.

Проверяйте наблюдаемое поведение, а не текст исходников или документации.
Не заводите мета-проверки, проверки формулировок, самопроверки стенда и
таблицы запрещённых слов. Сценарные помощники не содержат утверждений:
измеряемые обмены, число вызовов и сравнения остаются в самой проверке.
Для подмен используйте `unittest.mock.patch.object` / `patch.dict`.
Подробные правила и матрица очистки — в разделе «Проверки» архитектуры.
