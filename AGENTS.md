# Инструкции для агентов — день 18

Чат поверх OpenRouter: FastAPI, ванильный JS без сборки, SQLite; MCP-серверы
echo, git и remind. Python >= 3.11, Node.js для клиентских проверок.
Зависимости и версии — в `requirements.txt`.

Перед изменениями **прочитайте относящиеся к задаче разделы
[docs/architecture.md](docs/architecture.md)** и соответствующий исходник.
Для обменов чата читайте «Промпт и контекст» и «Хранение и ветвление»;
для UI — «Клиент»; для инструментов — «MCP и напоминания»;
для проверок — «Поведенческие проверки». Это действующие ограничения,
а не справка о прошлых днях. Общие команды и запуск агентов — в README.

## Безопасность

- Репозиторий публичный. Не читайте, не печатайте и не коммитьте секреты
  (`.env`, ключи), базы, диалоги и логи. Ключи не должны попадать в API,
  ошибки, хранилище или окружение дочерних MCP-процессов.
- Только `git add <конкретные файлы>`; никогда `git add .` или `git add -A`.
  Проверяйте staged diff перед коммитом. Утёкший ключ нужно отозвать;
  удаление из Git не устраняет утечку.
- Не делайте живых вызовов LLM. Проверки используют `checks/_stub.py`;
  ключ им не нужен. Smoke запускайте с временной `AGENT_DB_PATH` и
  `MCP_DISABLED=1`, без отправки сообщения модели.
- Настройки моделей и авторизации OpenCode/Pi — личные настройки инструмента.
  `mcp.json` принадлежит приложению; не превращайте его в конфиг агента IDE.

## Работа и проверка

```bash
make help
make setup                         # создать или использовать .venv
make setup PYTHON=/path/to/python  # Python >= 3.11; выбор только при создании
make run                           # http://127.0.0.1:8000
make check                         # весь набор, включая процессы и клиент
make check-browser                 # только клиент под Node.js
```

`setup` сохраняет существующие `.venv` и `.env`. Остальные цели всегда
используют `.venv/bin/python`. Не меняйте зависимости, схему, модели или
архитектурные границы попутно с документацией.

Проверки измеряют поведение: реальный клиент исполняется под Node.js на
`checks/dom.js`, сервер — со stub LLM и настоящими MCP-процессами где нужно.
Не добавляйте проверки формулировок документации, grep по исходнику,
самопроверки стенда или проверки про проверки. Утверждения, число обменов
и измеряемые вызовы оставляйте в самой проверке; helpers готовят сцену.
Подмены — `unittest.mock.patch.object` / `patch.dict`. Проверяйте очистку
на заполненных слоях, включая то, что обязано сохраниться; различающие
утверждения должны использовать действительно различающие значения.
