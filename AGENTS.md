# Работа в day-20

Чат поверх OpenRouter: FastAPI, обычный JS без сборки и SQLite. Точные
зависимости — в `requirements.txt`; Python >= 3.11, для проверок нужен Node.js.

## Перед изменениями

Прочитайте **соответствующие разделы [архитектуры](docs/architecture.md)**:
хранение и очистка, промпт и контекст, редактируемые слои, задачи, интерфейс,
MCP и инструменты, проверки. При сквозном изменении прочитайте все затронутые
разделы. Сверяйте факты с кодом этой ветки; не переносите устройство других дней.

## Безопасность

- Репозиторий публичный. Не читайте и не выводите секреты, `.env`, ключи,
  личные настройки авторизации; не коммитьте их, базы диалогов и `files/`.
- Используйте только `git add <конкретные файлы>`, никогда `git add .` или
  `git add -A`. Проверяйте состав и diff индекса перед коммитом.
- Не вызывайте живые модели. Проверки используют `checks/_stub.py`, работают
  офлайн и без настоящего ключа; smoke запускайте с временной базой и
  `MCP_DISABLED=1`. Не меняйте модель/провайдера ради проверки.
- `mcp.json` — конфигурация MCP **приложения**, не OpenCode/Pi. Модели и
  авторизация инструментов разработки — личные настройки вне репозитория.

## Команды из корня

```sh
make help
make setup                         # создаёт/переиспользует .venv, ставит requirements
make setup PYTHON=/path/to/python   # выбор Python только для создания .venv
make run                           # http://127.0.0.1:8000
make check                         # весь набор, включая subprocess и браузер
make check-browser                 # только клиент под Node.js
```

`setup` не создаёт и не перезаписывает `.env` и не пересоздаёт существующую
`.venv`; её интерпретатор тоже должен быть >= 3.11. Обычные цели используют
только `.venv/bin/python`. Проверки должны измерять поведение продукта,
исполнять настоящий клиент и различать проверяемые случаи; не добавляйте
проверки формулировок документации, исходного текста, стенда или самих проверок.
Подробные правила и ограничения стенда — в разделе «Проверки» архитектуры.
