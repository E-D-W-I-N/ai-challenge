# CLAUDE.md

## Что за проект

Чат-клиент поверх OpenRouter: FastAPI в `app/`, ванильный JS без сборки
в `app/static/`. Зависимости — три строки в `requirements.txt`.

## Среда

Системный `python3` — это 3.9, на нём код падает (`contextlib.aclosing`
из `app/agent.py` появился только в 3.10). Везде только 3.11:

```bash
/opt/homebrew/bin/python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000     # http://127.0.0.1:8000
```

## Безопасность

Репозиторий публичный, в `.env` лежит `OPENROUTER_API_KEY`: не коммитить
и не печатать. Никогда `git add -A` и `git add .` — файлы перечисляются точечно.
Живых вызовов к модели не делать: в проверках `stream_completion` подменяется
заглушкой из `checks/_stub.py`.

## Как прогнать проверки

```bash
.venv/bin/python checks/run_checks.py    # всё, включая три скрипта ниже и browser_check.js
.venv/bin/python checks/restart.py       # диалог переживает перезапуск процесса
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node
```

## Что нельзя ломать

- `provider.require_parameters: true` — на каждом вызове (`build_payload`, `app/llm.py`);
- `usage: {"include": true}` запрошен там же: без него нет ни `cost`, ни `reasoning_tokens`;
- незаданный параметр сэмплирования не отправляется вовсе: `None` — это не ноль;
- агент — отдельная сущность (`app/agent.py`), принимает текст, а не готовую ленту;
- сто чатов — сто объектов в одном процессе: ни потоков, ни подпроцессов, ни вызовов;
- конфиг копируется вглубь (`copy_spec`), и обмен идёт на слепке, снятом в начале `ask()`;
- откат по построению: ответа не случилось — в историю и в базу не пишется ничего;
- один обмен на чат: второй параллельный запрос получает `409`;
- память на SQLite (`app/store.py`): диалог переживает перезапуск, два процесса живут на одной базе;
- транзакция берёт блокировку сразу — `BEGIN IMMEDIATE`; не дождались — `503`, а не голый `500`;
- `redact()` на всех путях записи: писать можно только через `tx()`, ключа в базе нет ни в одной колонке;
- PK `(session_id, seq)`, история пишется целиком от нуля: `seq` без дыр, ленты сессий не сливаются;
- id чата выдаёт база (`claim_agent_id`), а не счётчик процесса;
- ключ не отдаётся наружу: в API едет только `has_key`, в интерфейсе про ключ ничего нет;
- клиент ничего не тянет из сети: иконки — inline SVG, markdown свой, текст экранируется до разбора.

## Про проверки

Проверки бьют по поведению, а не по исходнику. Греп по клиенту — не проверка
клиента: для него есть стенд `checks/dom.js`, он исполняет настоящий
`app/static/app.js` под node, с минимальным DOM и минимальным сервером,
который записывает, с каким конфигом ушло каждое сообщение. Мета-проверок
не заводить: ни таблиц запрещённых слов, ни самопроверок стенда, ни проверок
про проверки.
