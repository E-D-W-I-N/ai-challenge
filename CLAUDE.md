# CLAUDE.md

## Что за проект

Чат-клиент поверх OpenRouter: FastAPI в `app/`, ванильный JS без сборки в `app/static/`.
Зависимости — три строки в `requirements.txt`; клиент из сети не тянет ничего.

## Среда

Системный `python3` — это 3.9, на нём всё падает. Везде только 3.11.

```bash
/opt/homebrew/bin/python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000   # http://127.0.0.1:8000
.venv/bin/python -m app.cli                           # то же самое без браузера
```

## Безопасность

Репозиторий публичный, в `.env` лежит `OPENROUTER_API_KEY`: не печатать и не коммитить.
Никогда `git add -A` и `git add .` — перечисляй файлы точечно. Живых вызовов к модели
не делать: в проверках `stream_completion` подменяется заглушкой (`checks/_stub.py`).

## Как прогнать проверки

```bash
.venv/bin/python checks/spawn_100.py     # критерий дня: сто агентов в одном процессе
node checks/browser_check.js             # клиент под node
.venv/bin/python checks/run_checks.py    # всё сразу; первые два зовёт изнутри
```

`checks/dom.js` — не набор, а стенд: минимальный DOM и минимальный сервер, на которых
`browser_check.js` исполняет настоящий `app/static/app.js`.

## Что нельзя ломать

* `provider.require_parameters: true` на каждом вызове; `extra_body.provider` мержится поверх и обязан его сохранить.
* `usage: {"include": true}` запрошен — без него нет ни `cost`, ни `reasoning_tokens`.
* Незаданный параметр сэмплирования не уходит вовсе: ни как `null`, ни как ноль.
* Агент — отдельная сущность (`app/agent.py`): `ask()` берёт текст пользователя и сам склеивает промпт.
* Реестр (`app/registry.py`) — словарь в памяти: сто агентов это сто объектов и ноль вызовов к модели.
* Конфиг копируется вглубь (`copy_spec`): `stop`, `response_format`, `extra_body` у каждого свои.
* Обмен идёт целиком на слепке конфига, снятом в начале `ask()`.
* В модель уезжает вся история: ни окна, ни отсечки по росту.
* История не трогается до конца обмена: ответа не случилось — не записано ничего.
* Один обмен на агента: второй параллельный запрос получает `409`, бронь берётся до первого `await`.
* Ключ наружу не отдаётся: ручки возвращают только `has_key`, в интерфейсе про него ни слова.
* Клиент не ходит в сеть: относительные пути, inline SVG, свой markdown, экранирование **до** разбора.
* HTTP-клиент один на процесс, семафор `LLM_MAX_CONCURRENCY` держится на весь стрим.
* Памяти между запусками нет и не заводится: перезапуск стирает чаты и переписку.

## Про проверки

Проверки бьют по поведению, а не по исходнику. Греп по `app.js` — не проверка клиента:
для клиента есть стенд `checks/dom.js`, он гоняет настоящий код по всему маршруту —
правка в поле, отправка, тело запроса. Серверные смотрят на то, что ушло бы в модель
(`_stub.CALLS`), а не на ответ ручки. Мета-проверок не заводить: ни таблиц запрещённых
слов, ни самопроверок стенда, ни проверок про проверки.
