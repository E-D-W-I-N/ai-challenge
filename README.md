# День 14 — инварианты: чего ассистент не вправе предлагать

## Задание

```
🔥 День 14. Инварианты
Добавьте в ассистента инварианты, которые он не имеет права нарушать
(архитектура, технические решения, ограничения по стеку, бизнес-правила).
Инварианты хранятся отдельно от диалога; ассистент явно учитывает их;
отказывается предлагать решения, которые их нарушают.
```

Это первый из двух PR дня: слой — хранение, ручки, врезка в промпт, вкладка.
Сторож (проверка ответа по запрещённым словам) идёт вторым.

## Вывод

* **Слой хранится отдельно от диалога** — таблица `invariants` **без**
  `session_id`, как долговременная память и профиль: архитектура продукта
  не меняется от того, в каком чате о ней спросили. Удаление чата и `forget()`
  её не трогают, стирает один путь — `clear()`.
* **Инвариант едет системным сообщением**, четвёртым слагаемым к промпту чата,
  профилю и правилу этапа: системным едет то, что задал человек, а инвариант
  это распоряжение. Своего места в промпте он не занимает — номера врезок
  памяти от него не сдвигаются.
* **Запрещённые слова в промпт не уезжают ни одним символом.** Это знание
  сторожа, который смотрит на **ответ**. Перечисленный запрет сам по себе
  подсказка его употребить; и законный отказ стал бы невозможен — на «почему
  не Java?» ответить, не сказав «Java», нельзя.
* **Пишет в слой только человек**: пути у агента нет ни одного, и вид записи
  он тоже не выбирает — умолчания у вида нет ни в форме, ни на сервере.
* **Пустой слой неотличим от отсутствующего.** Иначе у чата без системного
  промпта и без профиля блок завёл бы собой системное сообщение и сдвинул
  номера всех врезок разом.

## Виды инвариантов

| вид | пример |
|---|---|
| архитектура | монолит, микросервисов не предлагать |
| техническое решение | очередь — Redis, не Kafka |
| ограничение стека | бэкенд только на Python |
| бизнес-правило | оплата только картой |

Ни одно слово не совпадает со словами соседних слоёв: «решение» уже занято
и долговременной памятью, и рабочей. Отсюда «техническое решение», а не
«решение» — иначе утверждение «это запись слоя инвариантов» было бы зелёным
и на чужой записи.

## Что уезжает в модель

```
system: СИС

        [как отвечать]
        стиль: кратко, на ты

        [чего нельзя]
        1. ограничение стека: бэкенд только на Python
        2. архитектура: монолит, микросервисов не предлагать
        Соблюдай это. Если просьба противоречит любому пункту — откажись
        и назови, какой именно нарушается.
```

Заголовок обычным русским, как `[как отвечать]` у профиля. Нумерация не
украшение: отказ обязан назвать, какой пункт нарушен, и номер — самый короткий
способ на него сослаться. Запрещённых слов в блоке нет.

Системное сообщение у чата по-прежнему **одно**. «Голый чат уходит без
системной реплики» осталось правилом, но голый теперь значит «ни системного
промпта, ни профиля, ни инвариантов».

## Что видно на экране

Вкладка **«Инварианты»** в панели: список с подписью вида, у каждой записи
правка на месте и корзина, внизу форма. Правятся все три поля разом — вид,
текст и запрещённые слова; слова видны строкой под инвариантом и **только
там**. Вид в форме не предвыбран: первым пунктом стоит «— выберите вид —»,
и без выбора форма не шлёт ничего.

Кнопка **«Показать промпт запроса»** под ответом показывает блок `[чего
нельзя]` в системном сообщении — и то, что запрещённых слов в нём нет.

## Хранение и ручки

Таблица `invariants`: `seq` AUTOINCREMENT (номер удалённой не выдаётся
заново), `kind`, `content`, `banned` — список слов JSON-массивом в одной
колонке, — и `at`. Ветвление слой не копирует: он глобальный, и ветка видит
его через то же хранилище.

| Ручка | Что делает |
|---|---|
| `GET /api/invariants` | все инварианты, со списками слов |
| `POST /api/invariants` | новый: `{"kind", "content", "banned"}`, слова необязательны |
| `PATCH /api/invariants/{seq}` | правка: любое подмножество трёх полей |
| `DELETE /api/invariants/{seq}` | убрать один |
| `/api/profile`, `/api/memory`, `/api/agents/{id}/working` | профиль и слои памяти |
| `/api/agents/{id}/task` | состояние задачи |
| `/api/agents/{id}/messages`, `/regenerate`, `/cancel`, `/fork` | обмен SSE, отмена, ветка |
| `/api/agents`, `/api/agents/{id}`, `/api/models`, `/api/health` | чаты, конфиг, каталог моделей, состояние сервера |

Вид обязателен и без умолчания (`_kind_field`), текст непустой
(`_content_field`), лишнее поле — 400, пустое тело правки — 400, чужой
номер — 404. Пустой список слов законен: у большинства инвариантов сторожить
нечего, их держит сам текст.

## Проверки

Живых вызовов к LLM нет — поток подменяется заглушкой. Бьют по поведению:
`browser_check.js` исполняет настоящий `app/static/app.js` под node на стенде
с минимальным DOM и настоящими кадрами SSE.

```bash
.venv/bin/python checks/run_checks.py    # 35 проверок, включая три ниже и клиентскую
.venv/bin/python checks/restart.py       # два процесса подряд на одном файле
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node, 343 утверждения
```

Про инварианты — две проверки. Первая: пустой слой неотличим от
отсутствующего; одиннадцать кривых тел дают 400; блок стоит четвёртой частью
единственного системного сообщения, а запрещённых слов нет ни в одном
сообщении промпта; у голого чата номера врезок сдвинулись на единицу
и вернулись после удаления записи; за обмен слой прочитан ровно один раз;
сжатию он не достаётся; ветвление копий не заводит. Вторая бьёт по **ответу**:
один вопрос, пустой слой против непустого — ответы расходятся, и запросы
различаются одним системным сообщением.

Таблица очистки «слой × путь» проходится целиком: семь слоёв на три пути,
двадцать одна клетка, четырнадцать уносят, семь **оставляют**.

## Как запустить

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000, вкладка **«Инварианты»**: впишите «бэкенд
только на Python», вид — «ограничение стека», запрещённые слова — «Java,
Kotlin». Спросите в чате «на чём писать бэкенд?». Без браузера — консоль
`.venv/bin/python -m app.cli`. `.env` и файлы базы — в `.gitignore`;
репозиторий публичный, не коммитьте через `git add -A`.
