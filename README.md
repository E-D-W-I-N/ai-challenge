# День 20 — оркестрация: несколько серверов, длинный флоу

```
🔥 День 20. Оркестрация
Несколько MCP-серверов. Агент выбирает нужный инструмент, корректно
маршрутизирует запросы, выполняет длинный флоу.
```

## Вывод

Оркестрация использует общий реестр `ToolRef`: независимые echo, Git,
pipeline и reminders подключаются по введённым оператором URL. Имена и коллизии
разрешает реестр, вызовы исполняет цикл дня 17, следующий шаг выбирает модель.
Payload содержит все публичные инструменты живых серверов с их описаниями и
схемами; host-only инструменты scheduler не объявляются модели.

День добавляет три проверки этого контракта:

* **Маршрутизация**: `git_log` и `ping` одним кадром, в порядке, обратном
  конфигу, возвращают результаты своих серверов. Порядок сохраняется в
  tool-сообщениях, бейджах и метриках.
* **Полный список**: инструменты echo, Git и pipeline в payload сверяются
  с `/api/mcp`, включая описания и схемы, без отдельного эталонного списка.
* **Изоляция отказа**: сервер с ошибкой initialize виден как down и не
  объявляет инструменты; остальные подключения и обмен продолжают работать.

Независимый сервис `services/pipeline` несёт три инструмента:

| инструмент | что делает |
|---|---|
| `search(query, limit=20)` | подстрока по репозиторию: `git grep -n -i -F --untracked`. Выдача отсортирована по (файл, строка) и только потом обрезана до `limit` — git свой порядок не обещает. Пустая выдача — честное «ничего не найдено», а не выдумка |
| `summarize(text, max_items=10)` | **механический** конденсат выдачи search: дедуп строк, группировка по файлам, обрезка до `max_items` групп — и обрезка названа числом. Без LLM принципиально: ключа у процесса нет |
| `save_file(name, content)` | пишет в каталог, выбранный оператором через `--files-dir`. Имя непустое, без краевых пробелов, «/», «\\» и «..»; отказ не создаёт файл |

Цепочку ведёт **модель**: цикл вызовов дня 17 сам доводит её до конца без
участия человека — search, видит результат, зовёт summarize с ним в
аргументе, затем save_file с выводом summarize. «Автоматическое выполнение»
— это «без человека», а не «мимо модели»: кода, передающего результат
одного инструмента в другой, нет. Передача данных — через tool-сообщения
рабочего списка, и на видео это три бейджа подряд под ответом
(`search · выбранный сервер · N мс` и т.д.), а файл появляется в выбранном каталоге.
Приложение не определяет Git-контекст или путь результата; сервис получает оба
от своего оператора и не импортирует Agent/Store/LLM.

Приложение подключается к независимо запущенному MCP-сервису по
**Streamable HTTP URL**. В широкой странице «Настройки → Инструменты» задайте
любое имя и URL, сохраните, затем нажмите «Подключить». Несколько строк позволяют
подключать разные сервисы; имена не зашиты в приложение. Видны статус, ошибка,
вызываемые имена инструментов, описания и схемы. В день 17 модель запрашивает
инструменты, агент исполняет их через MCP и отправляет новый запрос с результатом.
Цикл ограничен MAX_TOOL_ITER=4; ошибки аргументов/сервера возвращаются модели
как tool response, usage суммируется по раундам. Бейджи name/server/ms/ok видны
в потоке и сохраняются в метриках ответа. tools/tool_choice при пустом реестре
не объявляются; сжатие инструментов не получает.

Приложение не запускает MCP-сервисы автоматически. Сервис работает в другом терминале
и остаётся жив после «Отключить» и остановки приложения. URL и желаемое состояние
подключения общие для всех чатов, сохраняются в SQLite и переживают restart.
Изменённый URL требует нового явного подключения. При отказе можно исправить
URL или нажать «Подключить»/«Переподключить»; автоматического retry нет.

| Ручка | Что делает |
|---|---|
| `GET /api/mcp` | servers с name/url/status/error/tools, config с revision/servers, disabled |
| `PUT /api/mcp/config` | `{revision, servers:[{name,url,enabled}]}`; сохранить общие URL |
| `POST /api/mcp/connect`, `/api/mcp/disconnect` | `{name,revision}`; открыть/закрыть сессию |
| `POST /api/agents/{chat}/reminders/{server}/{id}/cancel` | снять свою задачу, включая активное выполнение |

Revision защищает от устаревших правок (409). URL допускает HTTP(S) endpoint без
логина, пароля, query и fragment; в этой версии нет UI настройки авторизации MCP.
Обмен целиком завершается до смены/закрытия сессии: Agent держит generic
`manager.lease()` от объявления инструментов до конца всех модельных раундов.

Штатный `mcp.json` пуст. `MCP_CONFIG_PATH` позволяет явно задать URL-конфиг или
legacy stdio fixture (`module`, `timeout_s`): только такими собственными дочерними
процессами менеджер управляет через terminate/kill; env ограничен PATH/HOME/LANG,
ключ OpenRouter не наследуется. Сохранённая UI конфигурация имеет приоритет.
`MCP_DISABLED=1` отключает transport; URL остаются доступными для редактирования.

Информация ответа показывает **фактические полные JSON-тела запросов** к
модели (messages, tools, параметры), снятые непосредственно перед отправкой.
Каждый раунд показан отдельно; журнал сохраняется вместе с assistant и остаётся
после refresh/restart и изменения настроек. Это не пересборка промпта по текущему
конфигу. Заголовки/ключи не сохраняются; известный ключ redact очищает до отправки.
Для старых сообщений написано «JSON запроса недоступен»; доступный legacy промпт
из события вкладки подписан отдельно. Токены/стоимость продолжают показываться.

## Общие команды

Из корня репозитория, с Python >=3.11, `make` и Node.js в PATH:

```bash
make help
make setup
# Если python3.11 не в PATH или нужен другой интерпретатор >=3.11:
make setup PYTHON=/path/to/python
make run             # http://127.0.0.1:8000, автоматическая перезагрузка
make check           # весь offline-набор, включая subprocess и клиент
make check-browser   # только клиентские проверки под Node.js
```

`PYTHON` выбирает интерпретатор только для создания `.venv`. Setup проверяет
версию, создаёт окружение при отсутствии или использует существующее и
устанавливает `requirements.txt`; повторный запуск сохраняет окружение.
Он не создаёт и не перезаписывает `.env`. Все последующие Python-команды
выполняются через `.venv/bin/python`; ошибки команд дают ненулевой exit code.

Для ручного диалога создайте `.env` из `.env.example`, только если его ещё
нет, и задайте `OPENROUTER_API_KEY` локально. Ключ не нужен offline-проверкам.
Секреты не выводите и не коммитьте; используйте только точечный `git add`,
никогда `git add -A` или `git add .`.

## Проверки

Живых вызовов к LLM нет: временная база, локальные заглушки, реальные
независимые HTTP MCP-фикстуры и явный stdio. `make check` покрывает HTTP
initialize/list/call, URL validation/save/restart/error/reconnect, сохранность
внешнего процесса, foreground tool/config race и lease между раундами.
Журнал сравнивается с JSON, фактически принятым HTTP-заглушкой провайдера:
три раунда, tools и tool response, неизменность после правки, restart/migration,
отсутствие auth/key. Проверка дня 17 использует настоящий Agent tool loop,
HTTP LLM MockTransport и независимо запущенный Git MCP, включая несколько
модельных раундов, реальные Git/tool результаты и гонку disconnect между раундами.
Также проверяются ошибки JSON/упавшего stdio-сервера, лимит четырёх вызовов,
суммы usage, попарная история без отдельных tool turns и отсутствие tools при
пустом реестре/сжатии. Клиент восстанавливает бейджи вызовов из метрик ответа.

День 19 сохраняет проверки алгоритмов search/summarize/save_file и legacy stdio.
Новый сквозной сценарий запускает отдельный HTTP pipeline с временными путями,
сохраняет и подключает его URL через API формы Tools, проводит четыре реальных
JSON-раунда модели с результатами предыдущих инструментов и проверяет байты
файла, usage, lease, SQLite/restart и JSON информации настоящего клиента.

День 20 сохраняет три сквозных orchestration-сценария: два сервера одним
кадром и обратный порядок конфигурации; полный список семи инструментов
трёх живых серверов; изоляция initialize-down зонда. Они запускают реальные
дочерние MCP-процессы с явно выбранным stdio-конфигом и offline-моделью.
Pipeline fixture использует временный Git/output и пакет `services` рядом с
`app`/`checks`, чтобы legacy shim импортировал независимую реализацию.
Production `mcp.json` остаётся пустым, ручные HTTP-подключения — штатным режимом.

Компактное клиентское ядро исполняет настоящий клиент под Node с заданными
ответами API/SSE: экранирование HTML и опасных ссылок, панель → запрос,
правильные область/id редакторов, partial PATCH профиля, сторож, MCP,
переключения во время потока и гонки команд задачи. Хранение, промпт,
переходы и суммы проверяет Python с offline-заглушками. Геометрию, подписи
и оформление проверяем вручную в настоящем браузере по
[короткому списку](docs/client-guide.md#ручной-прогон).

## Как запустить

После `make setup` запустите `make run` в одном терминале. В другом терминале
выполните из корня репозитория:

```bash
python3.11 -m venv /private/tmp/echo-mcp-venv
/private/tmp/echo-mcp-venv/bin/python -m pip install -r services/echo/requirements.txt
/private/tmp/echo-mcp-venv/bin/python -m services.echo --port 8016
```

У сервиса собственные зависимости; приложение для запуска не требуется.
Откройте «Настройки → Инструменты», введите имя `local` (или любое другое), URL
`http://127.0.0.1:8016/mcp`, сохраните и подключите. Появится `ping` с описанием
и схемой. Подробности и explicit stdio — в [services/echo/README.md](services/echo/README.md).

Для Git откройте ещё один терминал и явно выберите репозиторий:

```bash
python3.11 -m venv /private/tmp/git-mcp-venv
/private/tmp/git-mcp-venv/bin/python -m pip install -r services/git/requirements.txt
/private/tmp/git-mcp-venv/bin/python -m services.git --repo /absolute/path/to/repository --port 8017
```

Добавьте ещё одну строку с любым именем и `http://127.0.0.1:8017/mcp`.
У Git-сервиса свой путь и зависимости, без доступа к Agent/Store/LLM приложения.
Спросите «покажи последние коммиты»: модель может вызвать `git_log`, а под
ответом появится бейдж с именем инструмента/сервера и временем. Подробности —
в [services/git/README.md](services/git/README.md). Каждый сервис останавливается
Ctrl+C в собственном терминале; приложение его процессом не управляет.
Для пайплайна запустите ещё один независимый сервис в другом терминале:

```bash
python3.11 -m venv /private/tmp/pipeline-mcp-venv
/private/tmp/pipeline-mcp-venv/bin/python -m pip install -r services/pipeline/requirements.txt
/private/tmp/pipeline-mcp-venv/bin/python -m services.pipeline --repo /absolute/path/to/repository --files-dir /absolute/path/to/files --port 8019
```

Введите любое имя и `http://127.0.0.1:8019/mcp`, сохраните и подключите.
Репозиторий и каталог результата могут находиться отдельно от приложения.
Спросите «найди упоминания, сожми выдачу и сохрани в файл»; цепочкой управляет
модель. Запуск, алгоритмы и explicit stdio — в
[services/pipeline/README.md](services/pipeline/README.md). Если каталог результата
находится внутри выбранного репозитория, добавьте его в Git-ignore; `/files/`
в этом проекте уже игнорируется.

Без браузера чат доступен через `.venv/bin/python -m app.cli`.

Для отложенных задач запустите ещё один независимый сервис:

```bash
python3.11 -m venv /private/tmp/reminder-service-venv
/private/tmp/reminder-service-venv/bin/python -m pip install -r services/reminders/requirements.txt
REMIND_DB_PATH=/absolute/path/reminders.db REMIND_PORT=8001 /private/tmp/reminder-service-venv/bin/python -m services.reminders.server
```

Добавьте URL `http://127.0.0.1:8001/mcp` и подключите его. На просьбу
«Через 50 секунд проверь последние пять коммитов и опиши изменения» ответ
сразу подтвердит срок; Git-инструменты и итог запустятся после него. Результат
сам появится в исходном чате, даже если «Инструменты» закрыты. Выбранный чат
проверяется раз в секунду: совпавшая ревизия истории возвращает короткий ответ
без повторной передачи стенограммы. В «Инструментах» видны фактические
состояния; свою ожидающую или выполняющуюся задачу можно снять кнопкой.
Подробности [в README сервиса](services/reminders/README.md).

«Чат» и «Настройки» используют центральную рабочую область. Светлый интерфейс
рассчитан на компьютер и ноутбук: шесть страниц с вертикальной навигацией,
гибкие формы и сворачиваемый список чатов. Переключение сохраняет выбранный чат, черновик сообщения,
прокрутку, активный ответ и шапку задачи. Все шесть метрик доступны снизу;
в компактном окне строка прокручивается горизонтально. Длинный текст
переносится, код и JSON прокручиваются; при zoom можно свернуть список чатов.

Аватар справа в шапке открывает настоящий глобальный профиль: стиль, формат
и контекст ответа. Меню показывает записанные значения и ведёт в тот же
редактор «Профиль». Поля сохраняются при уходе фокуса; ошибка оставляет текст
для повторной попытки. Профиль, долговременная память и инварианты действуют
во всех чатах, модель, промпт и рабочая память — в выбранном чате.

Стрелки, Home и End переключают вкладки. Escape закрывает меню профиля
или подтверждение; фокус возвращается к открывшей
кнопке. В редакторе записи Enter сохраняет, Shift+Enter добавляет строку,
Escape отменяет. В обоих слоях памяти остаются ручное добавление, правка
и удаление с явным выбором типа записи. Поиск названий, копирование ответа
кнопкой и перенос рабочей записи кнопкой убраны; текст можно выделить
и перенести в форму долговременной памяти вручную.

Клиент загружает обычные локальные скрипты `text.js` → `records.js` → `app.js`,
без сборки и новых зависимостей. Карта файлов и чтения по задаче — в
[руководстве клиента](docs/client-guide.md).

## Пример длинного флоу

Для просьбы «собери отчёт и сохрани» модель может вызвать `git_log` и
`search` одним кадром, затем `summarize` с реальной выдачей, затем `save_file`
с выводом summarize; четвёртый запрос даёт финальный ответ. Независимые вызовы
внутри кадра исполняются последовательно. Клиент показывает вызовы под ответом,
файл появляется в выбранном оператором каталоге, а информация ответа хранит
все четыре фактических JSON-тела запроса.

Напоминание «через минуту проверь отчёт» отправьте отдельным сообщением.
Кадр с `remind` подтверждает срок и завершает текущий обмен: соседние вызовы
в этом кадре пропускаются, а отложенный запрос выполняется только после срока.
Его результат появляется в исходном чате, состояние видно в «Инструментах».
Выбор кадров принадлежит модели; offline-проверки измеряют контракт, а не
предсказывают поведение живой модели.

## Что осталось честно назвать

* **Модель решает сама**: `tool_choice` не шлём — позвать инструмент или
  ответить словами выбирает она; на вопрос не про репозиторий git она
  звать не станет, и это её право.
* **Вызовы внутри кадра последовательны**: порядок сохраняется между
  результатами, SSE и метриками; параллельного исполнения нет.
* **Промежуточный текст копится**: слова модели перед вызовом показываются
  и складываются с финальным ответом — честно, но на болтливой модели
  ответ может повторяться.
* **Автоматического переподключения нет**: упавший сервер получает down,
  вызов возвращает tool-сообщение с ошибкой. После запуска сервиса нажмите
  «Переподключить» в настройках.
* **Сторож запретов — отметка совпадения**: отказ, цитата вопроса и имя
  пакета могут дать ложное срабатывание; словоформы не распознаются.
  Ответ не скрывается и не переписывается.
* _Живой прогон на ключе:_ **место под числа оставлено пустым — впишет человек.**
