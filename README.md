# День 18 — напоминания: инструмент с отложенным выполнением

```
🔥 День 18. Отложенное выполнение
MCP-инструмент с отложенным или периодическим выполнением: сохраняет
данные, выполняется по расписанию, возвращает агрегированный результат.
```

## Вывод

Сервер `remind` (`app/mcp_servers/remind.py`) ведёт напоминания: модель
заводит их из диалога инструментом `remind`, человек смотрит во вкладке
«Инструменты» — и видит, как «ждёт» само становится «сработало». Три
инструмента: `remind` (одноразовое или с `every` — повторяющееся),
`reminders` (агрегированный результат: список с состояниями и счётчики),
`cancel` (чужой номер — честный отказ текстом).

| | |
|---|---|
| «Сработало» | **вычисляется при чтении** из `due_at` (`now >= due_at`), а не пишется: фонового цикла у сервера нет — он был бы вторым живым процессом у того же файла. У повторяющегося `due_at` при чтении всегда следующее, счёт срабатываний отсчитывается от первого срока |
| Хранение | своя база **сервера** `data/reminders.db` (SQLite, номера AUTOINCREMENT): сервер — её единственный писатель, стор приложения и его таблица очистки не тронуты. Переживает перезапуск процесса |
| Агрегат | `reminders()` → JSON: `items` (состояние, счёт, срок) плюс счётчики `total` / `waiting` / `fired`, сходящиеся со списком |
| В чат | **никогда**: история строго попарная, одиночная реплика сломала бы перегенерацию и свёртку. Человек видит напоминания во вкладке |
| Ручка | `GET /api/mcp` дотягивает `reminders` вызовом инструмента — только у живого сервера, у которого он есть; у лежачего поля нет, и ручка жива |

## Клиент

Во вкладке «Инструменты» у сервера с полем `reminders` — блок под его
инструментами: счётчики по состояниям и каждая запись с текстом и
временем. Пока вкладка открыта, она перезапрашивается раз в 2 секунды:
переворот «ждёт → сработало» виден живьём, без единого действия.
Закрыли вкладку — запросы прекратились.

## Проверки

Живых вызовов к LLM нет; механика сервера — in-process (функции модуля
обычные, REMIND_DB_PATH во временный каталог), связь — настоящими
процессами через тот же McpManager.

```bash
.venv/bin/python checks/run_checks.py    # 62 проверки, включая семь новых и клиентскую
.venv/bin/python checks/restart.py       # два процесса подряд на одном файле
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node, 377 утверждений
```

Новые: одноразовое срабатывает к сроку (статус вычисляется, а не пишется);
повторяющееся — несколько срабатываний и следующий `due_at`; `cancel`
снимает, чужой номер — отказ текстом, номер снятого не выдаётся заново;
агрегат сходится со списком; переживает перезапуск процесса (два
менеджера подряд на одном файле); у `/api/mcp` поле `reminders` только у
живого remind, у лежачего его нет — и ручка жива; сквозной (заглушка
зовёт `remind`, вызов доезжает до настоящего сервера, история остаётся
попарной). Клиентская: блок со счётчиками и временем, переворот виден
перезапросом, закрытая вкладка не опрашивается.

## Как запустить

```bash
cp .env.example .env    # впишите OPENROUTER_API_KEY; он в .gitignore
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

В `mcp.json` три сервера: `echo` (стенд связи), `git` и `remind`.
Спросите «напомни через минуту про чай» — под ответом будет бейдж
`remind · remind · N мс`, а во вкладке «Инструменты» запись перевернётся
в «сработало» на глазах. Репозиторий публичный: не коммитьте
`git add -A`.

## Что осталось честно назвать

* **Сработавшее молчит до вопроса**: уведомления в чат нет — история
  попарная. Человек узнаёт о срабатывании из вкладки или спросив модель
  («какие напоминания сработали?» — та позовёт `reminders`).
* **Точность — до перезапроса**: вкладка опрашивает раз в 2 секунды, и
  сервер считает состояние на момент чтения: сработавшее секунду назад
  видно с опозданием до двух секунд.
* **Часы — серверные**: `due_at` считается по часам процесса сервера;
  вкладка лишь показывает его ответ, сама по своим часам ничего не
  досчитывает.
* _Живой прогон на ключе:_ **место под числа оставлено пустым — впишет человек.**
