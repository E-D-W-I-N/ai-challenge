# День 15 — модель знает машину состояний

```
🔥 День 15. Явные переходы между состояниями задачи
Допустимые состояния, разрешённые переходы, ассистент не может
«перепрыгнуть» этап. Нельзя делать реализацию до утверждённого плана;
нельзя делать финал без валидации. Проверьте: попытки перейти
в недопустимое состояние, реакцию ассистента, продолжение после паузы.
```

## Вывод

Сам автомат построен в день 13 и не тронут: `TRANSITIONS` — единственная
таблица переходов, по ней ходят и команды, и ручки, незаконный ход — 409
и состояние прежнее. Не хватало одного: **машину знал только сервер**.

| | |
|---|---|
| Модель знает автомат | блок `[жизненный цикл задачи]` в том же единственном системном сообщении, рядом с правилом этапа |
| Блок собран **из таблицы** | ни один ход не выписан руками: добавили ребро в `TRANSITIONS` — модель назовёт его сама |
| Что в нём | весь граф, отметка «сейчас здесь», команда на каждый ход и запрет работать за чужой этап |
| Слота не завёл | `PROMPT_SLOTS` прежние, номера врезок памяти не сдвинулись |
| Реакция ассистента | просят работу другого этапа — отказ, называющий этап и ход |

```
system: СИС

        [этап задачи: планирование]
        Разложи задачу на шаги и ничего не выполняй.

        [жизненный цикл задачи]
        планирование — сейчас здесь: дальше (/task-next) → выполнение; пауза (/task-pause) → пауза
        выполнение: дальше (/task-next) → проверка; пауза (/task-pause) → пауза
        проверка: дальше (/task-next) → готово; пауза (/task-pause) → пауза
        готово: ходов отсюда нет, задача закончена
        пауза: продолжить (/task-resume) → туда, откуда встали
        Этап двигает только человек, этими командами. Просят работу другого
        этапа — не делай её: назови, чей это этап и каким ходом туда перейти.
```

Граф целиком, а не одни ходы отсюда: чтобы назвать, чья это работа, модель
обязана знать все этапы. «Нельзя делать финал без валидации» держится самой
таблицей — в `готово` ведёт единственное ребро, из `проверки`.

Отказ ручки при недопустимом переходе в историю по-прежнему не попадает:
его видит человек, а не модель. Модель знает машину **заранее** — и потому
объясняет, а не упирается в ход, которого не видела.

## Ручки

| Ручка | Что делает |
|---|---|
| `POST/PATCH/DELETE /api/agents/{id}/task` | включить; ход `{"move"}` или текст `{"step"\|"expects"}`; снять |
| отказы | ход не из таблицы — 409 с законными ходами; `from` назван и разошёлся — 409 с обоими этапами |
| прочие | `/api/invariants`, `/api/profile`, `/api/memory`, `/working`, `/messages`, `/fork`, `/api/agents`, `/api/models`, `/api/health` |

Команды набираются в поле ввода: `/task`, `/task-next`, `/task-step`,
`/task-expect`, `/task-pause`, `/task-resume`, `/task-off`.

## Проверки

Живых вызовов к LLM нет; `browser_check.js` исполняет настоящий `app.js` под node.
```bash
.venv/bin/python checks/run_checks.py    # 38 проверок, включая три ниже и клиентскую
.venv/bin/python checks/restart.py       # два процесса подряд на одном файле
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node, 350 утверждений
```

Новая — про знание машины: ходы в блоке сверяются с теми, что называет отказ
ручки; ребро, подложенное в таблицу, доезжает до блока; пять этапов — пять
разных блоков; у «готово» ходов нет. Последнее утверждение — про **ответ**:
заглушка читает блок там же, где прочитала бы его модель, и на «напиши код»
при планировании отвечает отказом, называя этап и ход; тот же промпт без
блока — и код пишется. Заглушка не модель: обещать она вправе только то,
что знание машины доезжает до ответа.

## Как запустить

```bash
cp .env.example .env    # впишите OPENROUTER_API_KEY; он в .gitignore
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

`/task собрать ТЗ` — и попросите написать код. Дальше `/task-next`,
`/task-pause`, `/task-resume`. Без браузера — `.venv/bin/python -m app.cli`.
Репозиторий публичный: не коммитьте `git add -A`.

## Что осталось честно назвать

* **Блок — распоряжение, а не запрет**: отказаться от чужой работы модель
  решает сама. Сервер не смотрит на ответ и не переспрашивает — отметки,
  как у сторожа инвариантов, у этапа нет.
* **Отказ ручки модель не видит**: 409 остаётся между человеком и сервером,
  в историю он не пишется. Это решение: разговор — не журнал нажатий.
* _Живой прогон на ключе:_ **место под числа оставлено пустым — впишет человек.**
