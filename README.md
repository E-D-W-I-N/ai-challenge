# День 06 — агент как отдельная сущность: чат-клиент со списком чатов

## Задание

```
🔥 День 6. Первый агент

Реализуйте простого агента, который:
👉 принимает запрос пользователя
👉 отправляет его в LLM через API
👉 получает ответ
👉 выводит результат в вашем интерфейсе

(простой чат, CLI или web, запросы через HTTP-клиент)

Важно:
👉 агент должен быть отдельной сущностью, а не просто один вызов API
👉 логика запроса и ответа должна быть инкапсулирована в агенте

Результат:
Агент принимает запрос и корректно вызывает LLM через API
```

Критерий проверки от организатора челленджа, дословно:

> Если тебе нужно будет моментально заспавнить 100 агентов с разными конфигами,
> у тебя это можно сделать? … Лучше чтобы инстанс был один, а уже внутри было
> поднято сто инстансов агента.

## Промпт

Промпта дня как такового нет: это чат, и вопрос задаёт пользователь. Зато
в списке слева уже заведены чаты с конфигами заданий дней 1–5 — по чату на
каждую колонку тех дней, двадцать один штука плюс обычный ассистент:

| Откуда конфиг | Чатов | Что в них |
|---|---|---|
| День 1 | 1 | `mistral-small-3.2-24b`, без параметров |
| День 2 | 6 | три пары «без параметра / с параметром»: `response_format`, `max_tokens=80`, `stop` |
| День 3 | 8 | четыре техники промптинга, включая панель из трёх ролей |
| День 4 | 3 | `temperature` 0.0 / 0.7 / 1.2 с закреплённым провайдером |
| День 5 | 3 | одна задача на трёх ступенях моделей |

Ничем особенным они не являются: это обычные чаты, которые уже заведены.
Их переименовывают, удаляют и правят наравне с теми, что создают кнопкой
«Новый чат», — отдельной ветки обработки под них в коде нет.

**Вопрос дня сам не отправляется.** Системная часть колонки уехала чату
в системный промпт, а вопрос — в черновик: у чата без переписки он подставлен
в поле ввода. Его видно, можно поправить, стереть и написать своё.

Перенос сверяется программно: `checks/run_checks.py` читает `day.py` каждой
ветки через `git show`, раскладывает колонки и сравнивает с чатами поле за
полем — модель, `temperature`, `max_tokens`, `stop`, `response_format`,
`extra_body` вместе с `provider.order`, системный промпт и текст вопроса.

## Вывод

### Интерфейс

Обычный чат-клиент.

- **слева** — заголовок с кнопкой свернуть, крупная кнопка «Новый чат»
  и **плоский список чатов**: ни групп, ни разделов, все чаты равны.
  У строки списка карандаш — переименовать на месте (Enter сохраняет,
  Escape отменяет) — и корзина с подтверждением. Внизу только переключатель
  светлой и тёмной темы;
- **по центру** — лента: сообщения пользователя справа компактным пузырём,
  ответ — карточкой с рамкой, в шапке имя модели и провайдер, справа иконки
  «метрики», «копировать», «перегенерировать», «сырой текст». Справа от ленты
  рельс с точками по сообщениям. Поле ввода **закреплено у нижнего края**:
  прокручивается лента, а не композер. Подсказка «Shift+Enter — новая строка»,
  во время генерации кнопка становится «Стоп» и действительно отменяет вызов;
- **справа** — две вкладки. «Модель»: выбор модели из каталога, `temperature`,
  `max_tokens`, `top_p`, `top_k`, `min_p`, три штрафа, окно памяти, формат
  ответа и стоп-строки. «Агент»: системный промпт. Ниже — строка состояния,
  ещё ниже плитки метрик.

Оба борта сворачиваются, состояние переживает перезагрузку. На узком окне
(до 940 px) они сворачиваются сами и открываются поверх ленты как ящики —
кнопками в углах, а закрываются кликом мимо и по Escape.

**Настройки применяются сами.** Отдельной кнопки «Сохранить» нет намеренно:
поле теряет фокус — правка уходит на сервер, и следующее сообщение уже идёт
с ней. Раньше кнопка была, и про неё было легко забыть: правка системного
промпта молча не доезжала до модели, а лента после ответа перерисовывала
панель и стирала несохранённый текст. Отправка сообщения ждёт незавершённую
правку, чтобы не обогнать её.

**Формат ответа и стоп-строки** — обычные поля панели, а не константы в коде.
Стоп-строки пишутся по одной в строке, без JSON. Формат ответа выбирается
списком: «не задан», «JSON-объект» или «свой JSON» с полем для нетривиального
значения; кривой JSON даёт понятную ошибку, а не уезжает провайдеру. Пустое
поле по-прежнему значит «не отправлять параметр» — а это не мелочь: на каждом
вызове стоит `provider.require_parameters: true`, и каждый заданный параметр
сужает список провайдеров, готовых обслужить запрос. Если после правки модель
становится недоступной, это видно ошибкой в карточке ответа.

**Имена чатов нумеруются**: «Новый чат 1», «Новый чат 2» и дальше. Счётчик
только растёт и номера не переиспользует — двух одинаковых имён по умолчанию
не бывает даже после удалений. Автоимени по первому сообщению нет.

**Про ключ в интерфейсе нет ничего** — ни пункта смены, ни упоминания:
репозиторий публичный, ключ живёт в `.env` и остаётся делом того, кто поднял
сервер.

**Из сети клиент не тянет ничего**: ни шрифтов, ни библиотек, ни иконок.
Шрифт системный, иконки — inline SVG, markdown разбирается своими силами
(заголовки, списки, цитаты, код, жирный, ссылки только на `http(s)`).
Текст ответа экранируется до разбора, поэтому разметка из ответа модели
не может стать разметкой страницы.

**Рассуждение.** Если модель прислала `reasoning` отдельным полем дельты,
оно показывается свёрнутым блоком «Рассуждение» над ответом. В контекст
следующего запроса рассуждение не возвращается: модель видит свой ответ,
а не то, как она к нему шла.

**Плитки метрик** — настоящие, из `app/llm.py`: ток/с, время до первого
токена, токены запроса и ответа, стоимость, время, провайдер, заполнение
контекста. Плитка «первый токен» показывает момент, когда модель заговорила,
а не когда пошёл ответ: на думающей модели это разные вещи, и `ttft_ms`
включал бы всё размышление. Насколько ответ отстал от рассуждения, видно
подписью справа на той же плитке.

### Агент

**Агент — класс** (`app/agent.py`). Публичный метод принимает **текст
пользователя**, а не готовую ленту: агент сам склеивает системный промпт,
окно истории и новый вопрос, зовёт `stream_completion` и дописывает ответ
себе в историю. Веб-слой ему не нужен — тот же класс работает из консоли
(`python -m app.cli`).

- **системный промпт живёт ровно в одном месте** — `spec.system` — и читается
  оттуда на каждом обращении. Если он приехал внутри `messages`, его переносят
  туда же при создании: иначе панель правила бы конфиг, а в модель уезжала бы
  копия, снятая в момент создания чата;
- **в истории лежит исходный текст вопроса**, а не собранный промпт;
- **кап двойной**: окно `history_limit` ограничивает то, что уезжает в модель,
  `MAX_STORED_MESSAGES` — то, что живёт в памяти процесса. Ноль в окне — чат
  отвечает каждый вопрос как первый;
- **откат по построению**: история не трогается до конца обмена. Ответа
  не случилось — не записано ничего, вопрос возвращается в поле ввода.
  Ответ частичный — записаны обе реплики, у ответа проставлена ошибка;
- **один обмен на чат одновременно** (`asyncio.Lock` плюс синхронная бронь
  до первого `await`): второй параллельный запрос получает `409`;
- **перегенерация заменяет последний ответ**: пара «вопрос — ответ» снимается
  с истории до вызова, поэтому модель видит тот же контекст, а в ленте
  остаётся один ответ. Если вызов не отдал ни одного токена, снятое
  возвращается на место — историю хранит сервер, и восстановить её было бы
  неоткуда.

**Реестр** (`app/registry.py`) — словарь `id → Agent`. Сто чатов с разными
конфигами — это сто объектов в одном процессе: ни потоков, ни подпроцессов,
ни единого вызова к модели. Есть потолок живых (`AGENT_MAX_LIVE`, по умолчанию
1000): при переполнении уходят самые старые простаивающие, занятый не
вытесняется никогда. За один запрос можно создать не больше 250 чатов.

Ответ на критерий организатора воспроизводится одной командой:

```bash
.venv/bin/python checks/spawn_100.py
```

```
[1] реестр: 100 агентов за 0.4 мс, живых 100
[2] POST /api/agents: 100 агентов за 2.0 мс (спавн внутри 0.53 мс), живых 122
[3] GET /api/agents: 122 живых, потолок 1000
[4] вызовов к модели за спавн: 0
[5] процесс один: pid=…, потоков 2, агентов 122
```

**Незаданный параметр не отправляется вовсе** — ни как `null`, ни как ноль.
Пустое поле в панели значит «пусть решает провайдер», а заданный ноль — это
заданный ноль.

**Клиент ленту не хранит.** Тело `POST /api/agents/{id}/messages` — это
`{"text": "…"}` и больше ничего; лишнее поле в теле получает `400`. Обрыв
клиента гасит вызов: брошенная вкладка иначе жгла бы токены. Один
`httpx.AsyncClient` на процесс, число одновременных вызовов ограничено
семафором (`LLM_MAX_CONCURRENCY`, по умолчанию 16).

### Чего в клиенте нет

Сценарии как концепция удалены целиком ещё раньше: `Scenario`, `SCENARIOS`,
`/api/run`, команда прогона, модель-судья, `depends_on` и серии `repeats`.
Вместе с ними ушли и последние следы витрины: группы чатов, «специальные»
агенты дней, пояснения из описаний сценариев (`note`), кнопка «Очистить все
чаты» и ручка `POST /api/agents/reset`, автоимя по первому сообщению.

`Session` остался тонкой обёрткой: `day.py` дней 1–5 объявляет колонки через
него вместе с `repeats`, `depends_on` и `note`, которых в конфиге больше нет,
и эти поля молча отбрасываются. Полной совместимости это не даёт: те же файлы
импортируют и `Scenario`. Настоящее чтение старых дней живёт в
`checks/_daysrc.py` со своим шимом — и на каждом прогоне проверок сверяет
чаты с ветками.

### Что помнит сервер между запусками

Ничего. Реестр живёт в памяти процесса: перезапуск стирает все чаты и всю
переписку, а заготовленные чаты поднимаются заново из `day.py`. Это не
недоделка, а ровно постановка задачи Дня 7.

### API

| Ручка | Что делает |
|---|---|
| `GET /api/agents` | плоский список чатов и наличие ключа |
| `POST /api/agents` | «Новый чат» (пустое тело), один чат или пачка |
| `GET /api/agents/{id}` | конфиг со стенограммой |
| `PATCH /api/agents/{id}` | имя, промпт, модель, память, сэмплирование, `stop`, `response_format` |
| `DELETE /api/agents/{id}` | удалить чат |
| `POST /api/agents/{id}/messages` | сообщение, тело — только `text`; SSE-поток |
| `POST /api/agents/{id}/regenerate` | перегенерировать последний ответ |
| `POST /api/agents/{id}/cancel` | погасить текущую генерацию |
| `GET /api/models` | каталог моделей для дропдауна |
| `GET /api/health` | ключ, реестр, потолок одновременных вызовов |

### Проверки

Живых вызовов к LLM в проверках нет ни одного — стрим подменяется заглушкой.

```bash
.venv/bin/python checks/spawn_100.py     # главный критерий дня
.venv/bin/python checks/run_checks.py    # все проверки, включая спавн сотни
node checks/browser_check.js             # клиент: markdown, раскладка, поля панели
```

`run_checks.py` проверяет спавн сотни, дословность переноса конфигов дней 1–5,
плоский список, применение правок панели к следующему сообщению (промпт,
модель, окно и все параметры), единственный дом системного промпта,
редактируемые `stop` и `response_format`, нумерацию имён, переименование
и удаление из списка, отсутствие «Очистить все чаты», отсутствие пояснений
и имени референса, закреплённый композер, память диалога и окно, `409`,
откат, гашение вызова при обрыве, `reasoning` и честное время до первого
токена, перегенерацию — удачную и провалившуюся, отсутствие ключа
в интерфейсе и в ответах, отсутствие обращений в сеть, глубину копии конфига,
вытеснение, потолок пачки, общий httpx-клиент, совместимость `Session` и CLI.

Клиентский код проверяется **исполнением, а не чтением**: `checks/browser_check.js`
подключает `app/static/app.js` под node и гоняет разбор markdown настоящими
payload'ами — экранирование, схемы ссылок, разметку внутри кода, — плюс разбор
стоп-строк и формата ответа и решение о раскладке узкого окна. Для этой части
нужен `node`; без него проверка честно падает, а не проходит молча.

## Как запустить

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000. Слева — список чатов; в заведённых заранее
вопрос уже подставлен в поле ввода, останется нажать Enter. Своя переписка
начинается с кнопки «Новый чат».

Без браузера, из консоли:

```bash
.venv/bin/python -m app.cli
.venv/bin/python -m app.cli --history-limit 0     # тот же агент без памяти
echo "привет" | .venv/bin/python -m app.cli --once
```

Переменные окружения: `LLM_MAX_CONCURRENCY` — потолок одновременных вызовов
к модели, `AGENT_MAX_LIVE` — потолок живых агентов в реестре.

`.env` в `.gitignore`. Репозиторий публичный: ключ, попавший в коммит, отозвать
уже нельзя — никогда не коммитьте через `git add -A`.
