# День 06 — первый агент: класс, реестр и команда `/прогон`

## Задание

```
🔥 День 6. Первый агент

Реализуйте простого агента, который:
👉 принимает запрос пользователя
👉 отправляет его в LLM через API
👉 получает ответ
👉 выводит результат в вашем интерфейсе

(простой чат, CLI или web, запросы через HTTP-клиент)

Важно:
👉 агент должен быть отдельной сущностью, а не просто один вызов API
👉 логика запроса и ответа должна быть инкапсулирована в агенте

Результат:
Агент принимает запрос и корректно вызывает LLM через API
```

Критерий проверки от организатора челленджа, дословно:

> Если тебе нужно будет моментально заспавнить 100 агентов с разными конфигами,
> у тебя это можно сделать? … Лучше чтобы инстанс был один, а уже внутри было
> поднято сто инстансов агента.

## Промпт

Сценарий дня сравнивает не модели, а **агентность**. Две колонки —
один и тот же агент, отличающийся ровно одним полем конфига, `history_limit`:

| Колонка | Модель | `history_limit` | Что показывает |
|---|---|---|---|
| С памятью · окно 20 | [`openai/gpt-4o-mini`](https://openrouter.ai/openai/gpt-4o-mini) | 20 | помнит весь разговор |
| Без памяти · окно 0 | [`openai/gpt-4o-mini`](https://openrouter.ai/openai/gpt-4o-mini) | 0 | каждый вопрос — первый |

Модель, системный промпт, `temperature=0.3` и `max_tokens=700` совпадают,
поэтому разницу можно приписать только памяти.

Системное сообщение:

```
Ты — помощник по планированию поездок. Отвечай по-русски, коротко,
обычным текстом без markdown-разметки: без звёздочек, решёток и таблиц.
Если тебе не хватает данных о поездке, не выдумывай их — прямо скажи,
чего ты не знаешь, и спроси об этом.
```

Первый вопрос — общий для обеих колонок, его задаёт «Старт»:

```
Меня зовут Нина. Еду в Казань на три дня в середине октября,
бюджет на всё — 20 000 рублей, я вегетарианка и не вожу машину.
Набросай план поездки по дням.
```

Второй и третий вопросы задаются руками, прямо в колонке, после «Старта»:

```
Что мне взять из одежды?
Где поужинать в первый вечер и сколько это будет стоить?
```

## Вывод

### Что демонстрируем

На первом вопросе колонки обязаны быть неотличимы: разговор только начался,
и помнить ещё нечего. Это контрольная точка, и её проверяет модель-судья.

Разница появляется со второго вопроса. Агент с памятью отвечает про
октябрьскую Казань, вегетарианское меню и остаток бюджета — про всё, чего
во втором вопросе нет. Агент с `history_limit=0` переспрашивает, куда и когда
едут: для него это первое сообщение в разговоре. Оба вопроса уходят на сервер
одинаково — строкой текста, — и вся разница в том, что агент подклеил к ней сам.

### Как это устроено

**Агент — класс** (`app/agent.py`). Публичный метод принимает **текст
пользователя**, а не готовую ленту: агент сам склеивает системный промпт,
стартовые сообщения, хвост истории и новый вопрос, зовёт `stream_completion`
и дописывает ответ себе в историю. Веб-слой ему не нужен — тот же класс
работает из консоли (`python -m app.cli`).

Четыре детали, каждая из которых иначе всплывает на прогоне:

- **в истории лежит исходный текст вопроса**, а не собранный промпт;
- **кап истории** двойной: окно `history_limit` ограничивает то, что уезжает
  в модель, `MAX_STORED_MESSAGES` — то, что живёт в памяти процесса;
- **откат по построению**: история не трогается до конца обмена. Ответа
  не случилось — не записано ничего, вопрос возвращается в поле ввода.
  Ответ частичный — записаны обе реплики, у ответа проставлена ошибка;
- **один обмен на агента одновременно** (`asyncio.Lock`): второй параллельный
  запрос к тому же агенту получает `409`, а не перемешивает историю. Серия
  `repeats` коммитит только последний удачный прогон из N.

**Реестр** (`app/registry.py`) — обычный словарь `id → Agent`. Сто агентов
с разными конфигами — это сто объектов в одном процессе: ни потоков, ни
подпроцессов, ни единого вызова к модели. Есть потолок живых агентов
(`AGENT_MAX_LIVE`, по умолчанию 1000) с вытеснением самых старых простаивающих:
процесс стенда живёт часами, и без вытеснения реестр течёт.

Ответ на критерий организатора воспроизводится одной командой:

```bash
.venv/bin/python checks/spawn_100.py
```

```
[1] реестр: 100 агентов за 0.2 мс, живых 100
[2] POST /api/agents: 100 агентов за 1.9 мс (спавн внутри 0.35 мс), живых 100
[3] GET /api/agents: 100 живых, потолок 1000
[4] вызовов к модели за спавн: 0
[5] процесс один: pid=…, потоков 2, агентов 100
```

**Команда `/прогон`.** Главный экран — чат с агентом. Строка, начинающаяся
со слэша, — команда (двойной слэш экранирует: `//прогон` уходит в модель
текстом). `/прогон 1` спавнит субагентов по колонкам сценария с `parent_id`
родителя и раздаёт им работу. Оркестрация та же, что была на пяти днях: та же
очередь, тот же `ready` для `depends_on`, та же отмена; изменилось одно — внутри
цикла вместо прямого вызова модели стоит вызов агента. Имена SSE-событий
прежние, к ним добавилось поле `agent`. Родитель дописывает себе в историю
сводку прогона, чтобы следующий вопрос в чате видел его в контексте.

**Судья — тоже агент**, и он спавнится свежим на каждый прогон: иначе он
потащил бы в контекст прошлые вердикты. Побочная выгода — он виден в реестре,
и у него можно спросить дальше, прямо в его сессии.

**Клиент ленту не хранит.** Тело `POST /api/agents/{id}/messages` — это
`{"text": "…"}` и больше ничего; лишнее поле в теле получает `400`, а не
молчаливое игнорирование. `POST /api/chat` удалён: единственной причиной его
существования было «клиент держит историю». Дропдаун модели теперь правит
живого агента через `PATCH /api/agents/{id}` — раньше он подмешивал `model`
в тело запроса, и после схлопывания тела до текста перестал бы работать.

**Обрыв клиента гасит вызов** и на POST-потоке тоже: брошенная вкладка иначе
жгла бы токены, а агент ещё и дописал бы недосмотренный ответ в историю.

**Один HTTP-клиент на процесс.** Раньше `httpx.AsyncClient` создавался внутри
каждого вызова — на сотне агентов это сотня пулов соединений. Теперь клиент
общий, а число одновременных вызовов к модели ограничено семафором
(`LLM_MAX_CONCURRENCY`, по умолчанию 16).

### Что помнит стенд между запусками

Ничего. Реестр живёт в памяти процесса: перезапуск стирает и агентов,
и все диалоги. Это не недоделка, а ровно постановка задачи Дня 7.

### API

| Ручка | Что делает |
|---|---|
| `POST /api/agents` | создать агента (`{"agent": …}`) или пачку (`{"agents": […]}`) |
| `GET /api/agents` | список живых агентов процесса |
| `GET /api/agents/{id}` | конфиг со стенограммой |
| `PATCH /api/agents/{id}` | сменить модель / `temperature` / `max_tokens` на живом |
| `DELETE /api/agents/{id}` | убить агента каскадом по детям |
| `POST /api/agents/{id}/messages` | сообщение агенту, тело — только `text`; SSE-поток |
| `POST /api/agents/{id}/cancel` | погасить текущую генерацию |
| `POST /api/scenarios/{i}/agents` | спавн колонок сценария до «Старта» |
| `GET /api/run/{i}` | прогон сценария, контракт событий прежний |
| `GET /api/health` | ключ, реестр, потолок одновременных вызовов |

### Проверки

Живых вызовов к LLM в проверках нет ни одного — стрим подменяется заглушкой.

```bash
.venv/bin/python checks/spawn_100.py     # главный критерий дня
.venv/bin/python checks/run_checks.py    # все проверки, включая спавн сотни
```

`checks/run_checks.py` проверяет спавн сотни, память диалога, отсутствие ленты
в теле запроса, `409` на двух параллельных запросах, серию `repeats`, откат
несостоявшегося обмена, гашение вызова при обрыве клиента, целость прогона
(`depends_on`, серия, судья, метрики, имена событий), команду `/прогон`
с экранированием, смену модели на живом агенте, каскадное удаление, вытеснение
по потолку, CLI и алиас `Session` для day.py прошлых дней.

## Как запустить

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000. Главный экран — чат. Выберите сценарий слева
(колонки станут живыми сессиями сразу, до «Старта»), нажмите «Старт» или
наберите в чате `/прогон 1`, а после первых ответов задайте колонкам второй
и третий вопросы руками.

Без браузера, из консоли:

```bash
.venv/bin/python -m app.cli
.venv/bin/python -m app.cli --history-limit 0     # тот же агент без памяти
echo "привет" | .venv/bin/python -m app.cli --once
```

Переменные окружения: `LLM_MAX_CONCURRENCY` — потолок одновременных вызовов
к модели, `AGENT_MAX_LIVE` — потолок живых агентов в реестре.

`.env` в `.gitignore`. Репозиторий публичный: ключ, попавший в коммит, отозвать
уже нельзя — никогда не коммитьте через `git add -A`.
