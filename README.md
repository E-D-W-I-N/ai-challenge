# День 16 — подключение MCP: соединение и список инструментов

```
🔥 День 16. Подключение MCP
Минимальный код, который устанавливает MCP-соединение и получает от MCP
список доступных инструментов. Проверьте: соединение устанавливается,
список инструментов корректно возвращается.
```

## Вывод

Приложение подключается к MCP-серверам по stdio: при старте поднимает по
процессу на сервер из конфига, здоровается по протоколу и забирает
`tools/list`. Список виден человеку — шестая вкладка «Инструменты»:
сервер, статус, инструменты с описанием и схемой параметров. Вызовов
инструментов моделью в этом дне нет — это день 17.

| | |
|---|---|
| SDK | официальный `mcp==1.30.0`, строгий пин; протокол весь на нём (`ClientSession`: initialize, tools/list, tools/call) |
| Процессы | запускает сам менеджер (`anyio.open_process`), не `stdio_client` — иначе `stop()` не за что гасить: terminate, через две секунды kill |
| Конфиг | `mcp.json` в корне (путь можно переопределить `MCP_CONFIG_PATH`); команда — всегда `sys.executable`, `cwd` — корень репо |
| Упавший сервер | down с причиной, приложение стартует дальше |
| Без конфига или `MCP_DISABLED=1` | менеджер пуст, приложение неотличимо от дня 15 |
| env дочерних процессов | белый список `PATH`, `HOME`, `LANG` — `os.environ` целиком не наследуется, `OPENROUTER_API_KEY` в subprocess не уезжает никогда |
| Коллизия имён | оба инструмента становятся `сервер__инструмент`, голого имени не остаётся |

```
mcp.json: {"servers": {"echo": {"module": "app.mcp_servers.echo", "timeout_s": 10}}}
GET /api/mcp → {"servers": [{"name": "echo", "status": "ok",
    "tools": [{"name": "ping", "description": "Проверка связи: …", "schema": {…}}]}]}
```

## Ручки

| Ручка | Что делает |
|---|---|
| `GET /api/mcp` | серверы: имя, статус ok/down, инструменты с описанием и схемой |
| прочие | без изменений: `/api/agents`, `/messages`, `/fork`, `/api/memory`, `/working`, `/api/profile`, `/api/invariants`, `/task`, `/api/models`, `/api/health` |

## Проверки

Живых вызовов к LLM нет; MCP-серверы локальные и поднимаются настоящими
процессами через тот же `McpManager`, что носит приложение.

```bash
.venv/bin/python checks/run_checks.py    # 45 проверок, включая шесть новых и клиентскую
.venv/bin/python checks/restart.py       # два процесса подряд на одном файле
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node, 364 утверждения
```

Новые шесть — по одному на инвариант дня: соединение и список с описанием
и схемой (плюс вызов `ping` и та же ручка через `TestClient`); коллизия
имён даёт префиксы обоим и голого имени нет; `stop()` гасит процесс —
и это SIGTERM, а не SIGKILL, так мутация «не terminate» не спрятана за
запасным kill; упавший на initialize сервер — down с причиной, сосед ok;
в env subprocess'а только белый список (зонд называет своё окружение
в тексте отказа); без конфига менеджер пуст и ручка отдаёт пустой список.
Седьмая строка — клиентская: вкладка ленивая, сервер со статусом,
схема свёрнута, пустой менеджер назван словами.

## Как запустить

```bash
cp .env.example .env    # впишите OPENROUTER_API_KEY; он в .gitignore
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Вкладка «Инструменты» в панели справа: сервер `echo` со статусом
«подключён» и инструмент `ping` с описанием и схемой. Без браузера —
`.venv/bin/python -m app.cli`. Репозиторий публичный: не коммитьте
`git add -A`.

## Что осталось честно назвать

* **Вызовов инструментов моделью нет**: `McpManager.call` написан и
  проверен, но из диалога его никто не зовёт — это день 17.
* **Подключение по одному на сервер за старт**: сервер, упавший после
  рукопожатия, остаётся down до перезапуска приложения — переподключения
  нет.
* **Серверу верим на слово**: схема и описание показываются как приехали,
  без валидации; мусор в stdout сервера уезжает в поток исключением,
  по образцу транспорта SDK.
* _Живой прогон на ключе:_ **место под числа оставлено пустым — впишет человек.**
