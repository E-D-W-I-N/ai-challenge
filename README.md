# День 17 — вызов инструментов: цикл в агенте и git-сервер

```
🔥 День 17. Вызов инструментов
Реализуйте вызов инструментов: модель запрашивает вызов, приложение
исполняет его на MCP-сервере, результат возвращается в диалог.
```

## Вывод

Модель зовёт инструменты из диалога: агент объявляет их в запросе,
исполняет на настоящих MCP-серверах и повторяет запрос с результатами.
Под каждым ответом — бейджи вызовов: имя, сервер, миллисекунды, пометка
об ошибке. Пустой менеджер (нет конфига, `MCP_DISABLED=1`) неотличим от
дня 15: ни процессов, ни ключа `tools` в теле.

| | |
|---|---|
| Объявление | `tools` в теле — только при непустом реестре, из `server.view` (описание и схему отдал сам сервер); `tool_choice` не шлём |
| Цикл | стрим → событие `tool_calls` → исполнение через `MANAGER.call` → `role: "tool"` с результатом → повторный стрим; лимит `MAX_TOOL_ITER = 4`, исчерпан — накопленный текст отдан, в метриках `tool_iterations` |
| Ошибки | битый JSON аргументов и упавший сервер — tool-сообщение с текстом ошибки и кадр `ok: false`, а не падение обмена |
| История | попарная всегда: tool-сообщения живут в рабочем списке обмена и в базу не пишутся никогда; следующий обмен видит только финальный ответ |
| Метрики | `metrics["tool_calls"] = [{name, server, ms, ok}]`; usage складывается по итерациям — вызовы модели после первого оплачены |
| Сжатие | инструменты ему не объявляются: оно пересказывает разговор, вызовы ему ни к чему |
| Git-сервер | `app/mcp_servers/git.py`: `git_log`, `git_status`, `git_diff_stat` — subprocess git в корне репо, без shell, с таймаутом; ругань git на плохой ref едет ответом, не прячется |

```
модель: tool_calls → git_log {"n": 1}
агент: MANAGER.call → SSE tool_call {name, server, ms, ok}
модель ← assistant(tool_calls) + role:"tool" (настоящий коммит)
модель: финальный ответ, впитавший результат
```

## Клиент

Бейдж вызова — своя строка под ответом, как отметка сторожа: встаёт из
кадра `tool_call` ещё до конца обмена, после перерисовки читается из
`metrics.tool_calls`. Упавший вызов помечен «ошибка вызова:». Вкладка
«Инструменты» показывает серверы и прокручиваемые схемы.

«Чат» и «Настройки» используют центральную рабочую область. Светлый интерфейс
рассчитан на компьютер и ноутбук: шесть страниц с вертикальной навигацией,
гибкие формы и сворачиваемый список чатов. Переключение сохраняет выбранный чат, черновик сообщения,
прокрутку, активный ответ и шапку задачи. Все шесть метрик доступны снизу;
в компактном окне строка прокручивается горизонтально. Длинный текст
переносится, код и JSON прокручиваются; при zoom можно свернуть список чатов.

Аватар справа в шапке открывает настоящий глобальный профиль: стиль, формат
и контекст ответа. Меню показывает записанные значения и ведёт в тот же
редактор «Профиль». Поля сохраняются при уходе фокуса; ошибка оставляет текст
для повторной попытки. Профиль, долговременная память и инварианты действуют
во всех чатах, модель, промпт и рабочая память — в выбранном чате.

Стрелки, Home и End переключают вкладки. Escape закрывает меню профиля
или подтверждение; фокус возвращается к открывшей
кнопке. В редакторе записи Enter сохраняет, Shift+Enter добавляет строку,
Escape отменяет. В обоих слоях памяти остаются ручное добавление, правка
и удаление с явным выбором типа записи. Поиск названий, копирование ответа
кнопкой и перенос рабочей записи кнопкой убраны; текст можно выделить
и перенести в форму долговременной памяти вручную.

Клиент загружает обычные локальные скрипты `text.js` → `records.js` → `app.js`,
без сборки и новых зависимостей. Карта файлов и чтения по задаче — в
[руководстве клиента](docs/client-guide.md).

## Проверки

Живых вызовов к LLM нет; MCP-серверы поднимаются настоящими процессами.

```bash
make check             # весь набор: сервер, subprocess-сценарии и клиент
make check-browser     # только настоящий клиент под Node.js
```

Компактное клиентское ядро использует явные API/SSE-фикстуры; формулы
промпта, суммы и переходы проверяются на Python, без второго сервера в JS.
HTML-путь исполняет три настоящих скрипта без CommonJS. Геометрию и клавиши
проверяйте по [ручному списку](docs/client-guide.md#ручной-прогон).

Новые: сквозной сценарий (заглушка просит `git_log`, агент исполняет на
настоящем сервере, второй запрос несёт `role: "tool"` с настоящим
коммитом, ответ его пересказывает); `tools` только при непустом реестре;
битый JSON и вышедший MCP-процесс — tool-сообщение с ошибкой; пять оборотов — стоп на
`MAX_TOOL_ITER`; usage по итерациям сложен; история в базе попарная и
`seq` без дыр; сжатию инструменты не объявляются; git-сервер по живому
процессу (журнал настоящий, ругань git не спрятана); остановка приложения
с двумя серверами чистая (стеки LIFO). Клиентская: бейдж из события до
конца обмена и из метрик после перерисовки, упавший помечен, строка
чисел не тронута.

## Как запустить

```bash
make help
make setup
# Только если .env ещё нет: создайте из шаблона, затем впишите ключ вручную.
test -e .env || cp .env.example .env
make run               # http://127.0.0.1:8000
```

Команды выполняются из корня checkout. Нужны Python >= 3.11 и Node.js для
проверок. `PYTHON ?= python3.11` выбирает Python только при создании среды:
`make setup PYTHON=/path/to/python`. Существующая `.venv` переиспользуется,
requirements устанавливаются в неё; setup не создаёт и не перезаписывает
`.env`. run/check используют `.venv/bin/python`. run запускает
`-m uvicorn app.main:app --reload --port 8000`. Ошибки команд возвращают
ненулевой код; `make check` вызывает `checks/run_checks.py` один раз, включая
`restart.py`, `two_processes.py` и браузерный сценарий.

В `mcp.json` два сервера: `echo` (стенд связи) и `git`. Спросите «покажи
последние коммиты» — под ответом будет бейдж `git_log · git · N мс`.
Репозиторий публичный: не выводите секреты и базы с диалогами, добавляйте
файлы в git только явным перечнем, без `git add .` и `git add -A`.

## Работа через OpenCode или Pi

Установленный инструмент запускайте из корня этого checkout:

```bash
cd /path/to/ai-challenge-9-week-01
opencode
# Или в отдельной сессии:
pi
```

[OpenCode](https://opencode.ai/docs/rules/) и
[Pi](https://github.com/earendil-works/pi/tree/main/packages/coding-agent#context-files)
автоматически загружают корневой `AGENTS.md` в контекст. Инструкции в нём
обязуют прочитать нужные разделы `docs/architecture.md` перед изменениями:
саму ссылку инструмент не обязан раскрывать автоматически. Для Pi список
загруженных файлов виден в заголовке запуска.

Модель и авторизацию выбирайте в личных настройках инструмента: OpenCode —
`opencode auth login` и пользовательская конфигурация, Pi — `/login`, `/model`
и настройки в `~/.pi/agent/`. Эти настройки и ключи не коммитятся в проект;
они не меняют модели/OpenRouter приложения. `mcp.json` принадлежит приложению
и не является конфигурацией MCP для OpenCode или Pi. Расширения и отдельные
конфиги инструментов для чтения `AGENTS.md` не нужны.

Проверки работают с заглушкой без ключа, живые вызовы LLM агентам запрещены.
Для smoke используйте временную `AGENT_DB_PATH`, `MCP_DISABLED=1` и
`GET /api/health`; не отправляйте сообщение модели.

## Что осталось честно назвать

* **Модель решает сама**: `tool_choice` не шлём — позвать инструмент или
  ответить словами выбирает она; на вопрос не про репозиторий git она
  звать не станет, и это её право.
* **Промежуточный текст копится**: слова модели перед вызовом показываются
  и складываются с финальным ответом — честно, но на болтливой модели
  ответ может повторяться.
* **Переподключения нет**: сервер, упавший после рукопожатия, — down до
  перезапуска приложения; вызов на нём кончится tool-сообщением с ошибкой.
* **Сторож запретов — отметка совпадения**: отказ, цитата вопроса и имя
  пакета могут дать ложное срабатывание; словоформы не распознаются.
  Ответ не скрывается и не переписывается.
* _Живой прогон на ключе:_ **место под числа оставлено пустым — впишет человек.**
