# День 13 — состояние задачи: план и есть состояние

## Задание

```
Реализуйте состояние задачи как конечный автомат: этап задачи, текущий шаг,
ожидаемое действие. Пример: planning → execution → validation → done.
Проверьте: паузу на любом этапе; продолжение без повторных объяснений.
Результат: агент с формализованным состоянием задачи.
```

## Что сделано

* **План и есть состояние**: шаги со статусами (`pending` / `in_progress` /
  `done`) и три флажка — утверждён, завершена, на паузе.
* **Этап не хранится, а вычисляется** — `plan.stage_of`, единственное место;
  разбор упорядоченный, потому что условия этапов пересекаются.
* **Три поля задания — из того же списка**: этап, текущий шаг, ожидаемое
  действие (правило этапа для модели, уместные кнопки для человека). Отсюда
  даром: шаг вернулся в `pending` — этап сам пересчитался в работу.
* **Два инструмента у модели** — `update_plan` (весь список) и `finish_task`
  (перечень проблем; пустой — задача завершена); **пять кнопок у человека** —
  утвердить, переоткрыть, пауза, продолжить, сброс. Переходы решает один
  `plan.apply`, имена для модели взяты из самого объявления.
* **Отказ — блокирующая директива, а не код ошибки**: что не произошло,
  почему, запрет заявлять успех, что допустимо взамен, и план целиком.
* **Перечень проблем вместо «годно?»** — форму массива держит провайдер.
* **Один сделанный шаг — один обмен.** Обмен — цикл оборотов: вызов
  исполнен, слово за моделью; **план продвинулся** (шаг стал `done` или
  вышел из него, список изменился составом, сменился флажок) — инструменты
  гаснут, модель договаривает словами. Взятие шага в работу продвижением
  **не** считается: погаси вызовы на нём — и отметить сделанное нечем,
  модель дорисует отметку словами. Дальше клиент продолжает сам, пока план
  продвигается и работа идёт, не больше двенадцати обменов; у каждого шага
  своя карточка и своя кнопка «Показать промпт запроса». Текст продолжения —
  короткое **указание** на переход: следующий шаг, «проверяй», «исправляй»;
  что делать и каким вызовом, говорит правило этапа, оно свежее.
* **Правило этапа и блок `[задача]` пересобираются перед каждым оборотом**,
  переписыванием на месте: номера врезок не сдвигаются.
* **Промолчать не дают кодом.** На планировании `tool_choice` называет
  `update_plan` — законный вызов там один. На проверке законных два
  (`finish_task` или возврат шага), и поле требует позвать **любой**:
  вердикт за моделью, молчание не вариант. На остальных этапах поля нет.
* **Оборот без инструментов знает, что он без инструментов**: правило этапа
  договаривает «ничего не обещай». Иначе модель пишет «вызываю finish_task»
  вместо вызова, а на следующем обмене читает это как сделанное дело.

## Что видно на экране

1. **Обычный чат.** В подсказке поля ввода — «/task задача — режим задачи».
2. **`/task собрать ТЗ`** — пузырь без `/task`, шапка «Задача · план».
3. **Модель зовёт `update_plan`** — шапка «утверждение» со списком шагов,
   ещё до конца ответа.
4. **План записан** — инструменты гаснут, модель договаривает словами;
   под ответом «оборотов 2», в шапке «Утвердить план».
5. **«Утвердить план»** — пузырь встаёт сам, шапка «работа, шаг 1 из 5».
6. **Модель работает** — обмен на каждый сделанный шаг: `○` → `▶` → `✓`,
   следующий обмен клиент шлёт сам. Под каждым свои числа.
7. **Все шаги `✓`, этап «проверка»** — тем же порядком, своей карточкой
   и своим промптом: в нём видно «шаг k из 5», с которым уехал обмен.
8. **`finish_task`** — пусто: «готово»; проблемы: этап вернулся в работу.
9. **«Выйти из режима задачи»** — шапка убрана, чат снова обычный.

## Пауза и продолжение

* законна на любом незавершённом этапе: `planning`, `approval`, `execution`,
  `validation`;
* оба инструмента модели отказаны на ней **кодом** — «продолжай» в чате
  паузу не снимает;
* поля `paused_from` нет: пауза список не трогает, этап вернулся сам;
* продолжение без повторных объяснений: список и флажки в базе.

## Хранение

| таблица | что в ней |
|---|---|
| `task_state` | `session_id` первичным ключом, три флажка, время |
| `task_steps` | `session_id`, `seq`, `title`, `status`; PK `(session_id, seq)` |

Две, а не одна с JSON: флажки живут и у пустого списка. `seq` — от нуля без
дыр, список переписывается снимком одной транзакцией. `DELETE` из обеих
таблиц — на всех трёх путях очистки: удаление чата, очистка базы, `/забыть`;
ветка уносит план целиком. **Миграций нет**: `_migrate` снесён.

## API

| Ручка | Что делает |
|---|---|
| `POST /api/agents/{id}/plan/approve` | утвердить — только на этапе `approval` |
| `POST /api/agents/{id}/plan/reopen` | переоткрыть — только завершённую |
| `POST /api/agents/{id}/plan/pause` | пауза — на любом незавершённом этапе |
| `POST /api/agents/{id}/plan/resume` | снять паузу |
| `POST /api/agents/{id}/plan/reset` | сброс: пустой список, флажки сняты |

Отвечают планом целиком, с вычисленными `stage` и `current`. Не тот этап или
занятый агент — 409. Ключ `plan` есть в теле чата всегда.

## Проверки

Живых вызовов к модели нет — поток подменяется заглушкой.

```bash
.venv/bin/python checks/run_checks.py    # 37 проверок, включая три ниже и клиентскую
.venv/bin/python checks/restart.py       # два процесса подряд на одном файле
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node, 388 утверждений
```

Было 30 проверок, стало 37. Новых семь: вызовы инструментов; состояние
задачи; цикл оборотов; свежее правило на каждом обороте; сделанный шаг
кончает обмен; обязательный план на планировании; метрики как сумма
оборотов. Пауза
проходится на **всех** незавершённых этапах; на каждое новое утверждение
прогнана мутация.

## Как запустить

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000, напишите `/task собери план проверки формы
регистрации` и дальше идите по кнопкам шапки: «Пауза» посреди работы — и
модель откажется продолжать, «Продолжить» — и работа пошла с того же шага.

Без браузера — консоль: `.venv/bin/python -m app.cli` (плюс `--session <id>`
и `--once`); внутри `/выход`, `/история`, `/забыть`, `/агенты`, `/сессии`.
Переменные окружения — `AGENT_DB_PATH`, `LLM_MAX_CONCURRENCY`, `AGENT_MAX_LIVE`.

`.env` и файлы базы — в `.gitignore`. Репозиторий публичный: ключ, попавший
в коммит, отозвать уже нельзя — не коммитьте через `git add -A`.
