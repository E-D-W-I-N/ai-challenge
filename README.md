# День 13 — состояние задачи: этап двигает инструмент модели

## Задание

```
🔥 День 13. Состояние задачи

Реализуйте состояние задачи как конечный автомат:

👉 этап задачи
👉 текущий шаг
👉 ожидаемое действие

Пример состояний: planning → execution → validation → done

Проверьте:

👉 паузу на любом этапе
👉 продолжение без повторных объяснений
```

Вчера агент научился говорить **с этим человеком**. Сегодня он знает,
**где стоит задача**: на каком она этапе, что делается сейчас и какого
действия ждут, — и двигает её сам, вызывая инструмент, когда продвинулся.

## Вывод

### Этап — закрытый список из четырёх, и он меняет поведение

```
планирование → работа → проверка → готово
                  ▲         │
                  └─────────┘   проверка нашла проблемы — назад в работу
```

Плюс два поля свободным текстом: **текущий шаг** и **что ожидается**.

Строка из закрытого списка, как `strategy`, и по тем же двум доводам: `bool`
отбрасывается разбором полей (в Python `True` — это `int`), а `Literal`
не по зубам разбору проб round-trip.

**У каждого этапа своя инструкция**, и она уезжает в промпт вместе
с состоянием: чем заняты, чего ждут и **когда звать инструмент**. Зашитое —
умолчание, а не закон: **набранное человеком побеждает**. Вписал «сейчас»
руками — едет его, поле он для того и трогал.

**Карта разрешённых переходов** отбивает прыжки через этап. Обратное ребро
`проверка → работа` в ней главное: проверка, нашедшая проблемы, обязана
возвращать задачу в работу — иначе «проверка» слово, а не момент.

### Этап двигает инструмент модели, а карта держит маршрут

Вчерашний механизм был другим: после **каждого** обмена мы спрашивали
у модели перечень недостающего и двигали этап по её ответу. На живом прогоне
он не сработал дважды, а платить за него приходилось лишним обращением
к модели на каждом обмене.

Сегодня это сделано так, как это делают все: **модель сама вызывает
инструмент**, когда поняла, что продвинулась.

```
update_stage(stage: planning | execution | validation | done)
```

> Обнови этап задачи. Вызывай, когда продвинулся: план готов и утверждён,
> работа сделана, проверка проведена. Не вызывай, если ничего не изменилось.

Лишний оборот случается только при настоящей смене этапа — три раза
за задачу вместо двадцати. И решение приезжает **формой**, которую держит
провайдер: аргументом из закрытого списка. Разбора текста не осталось нигде,
и это главный вывод дня — на нём мы обожглись трижды.

**Объявляется инструмент только там, где есть что двигать**: на «работе»
и «проверке». На планировании его нет — выход оттуда один, кнопка человека,
и объявить инструмент там значило бы предложить модели дверь, которой
у неё нет. На «готове» его нет тоже: карта не ведёт никуда. Пустой чат
поэтому и дешевле: в теле запроса нет даже объявления.

**Модель просит — код решает.** Проверка перехода стоит там же, где стояла:
в карте. Разрешён — записываем, журнал получает строку с пометкой «агент».
Запрещён — **не записываем**, а модель получает ответ по существу:

```
готово, этап теперь: validation
этап уже такой: execution, менять нечего
нельзя: из execution можно только в validation
нельзя: из planning задачу выпускает только человек, кнопкой «Утвердить план»
нет такого этапа. Допустимые: planning, execution, validation, done
```

Не «ок» и не «ошибка»: ответ читает модель и на нём продолжает. Получив
отказ с доводом, она поймёт, что делать дальше, а получив «ошибку» —
повторит то же самое.

Повторный вызов с тем же этапом — **не ошибка и не переход**: ничего
не записываем, в журнал не пишем, отвечаем спокойно. Иначе журнал зарастёт
строками ни о чём, а модель решит, что сделала что-то не так.

**Одного инструмента мало.** Модель, у которой есть кнопка, но нет повода,
её не нажмёт — ровно на этом развалилась автоматическая запись памяти днём
раньше. Поэтому «когда пора» написано в самом блоке задачи, строкой
инструкции этапа:

```
инструкция: работай, а не обещай работать: выдавай результат сразу
            и разрешения на каждый шаг не спрашивай; держись утверждённого
            плана, не меняй решений молча; работа сделана — вызови
            update_stage(stage="validation")
```

Описание инструмента объясняет, **что** он делает; блок задачи — **когда**
пора его звать.

### Оборот обмена

В `app/llm.py` инструментов не было вовсе. Появились три вещи: `tools`
в теле запроса (незаданное не отправляется вовсе — идиом тот же, что
у параметров сэмплирования), вылов вызовов из потока и признак конца хода
по вызову.

Вызовы приезжают **кусками** и собираются по `index`: имя и id в первом
куске, `arguments` — строкой, растущей от куска к куску, вперемешку
с соседним вызовом. Ход, кончившийся вызовом, кончается им и для нас:
`finish_reason` у такого чанка — `tool_calls`, и текста в нём может
не быть вовсе.

В `app/agent.py` — цикл: получили вызов → исполнили → дописали результат
в сообщения → пошли за продолжением. Продолжение стримится собеседнику
как обычный ответ, потому что оно и есть обычный ответ: модель просто
успела по дороге сходить за кнопкой.

**Оборотов не больше двух подряд.** Упрямая модель иначе уведёт обмен
в круг. На последнем обороте инструмент **не объявляется вовсе**: оставь
мы объявление, модель позвала бы снова, мы бы снова прервались на предел,
и собеседник остался бы без ответа — ход, кончившийся вызовом, текста
не отдаёт.

**Метрики обоих оборотов** складываются в числа обмена: оборот с вызовом
стоит денег наравне с ответом, и отчёт, назвавший только второй, соврал бы
о цене инструмента вдвое. Складывается ровно вход, выход, всего и цена;
время до первого токена и скорость — про один вызов, и сумма из них ничего
не значит.

Отмена и падение работают как прежде: оборванный обмен пишется частичным,
ошибка — кадром `error`.

### У каждого перехода ровно один механизм

```
планирование → работа     кнопка «Утвердить план»
работа → проверка         инструмент
проверка → готово         инструмент
проверка → работа         инструмент
```

Ручного переключения этапов не осталось: **полоса — показ, а не пульт**.
Второй механизм на тот же переход — это две правды об одном, и расходятся
они молча. `PATCH /task` правит только тексты «сейчас» и «ожидается»;
`stage` для неё лишнее поле, и ответ на него — 400.

Кнопка «Утвердить план» осталась и осталась единственным выходом
из планирования. Это не запасной путь, а гейт по замыслу: утверждение плана —
решение человека, и выводить его из разговора нельзя. У неё своя ручка,
`POST /api/agents/{id}/task/approve`, и обе двери ведут в одну —
`Agent.move_stage`, где стоит карта.

### Отдельного блока в промпте нет

Состояние едет в **тот же** блок, что рабочая память, и первыми его строками:

```
[факты о разговоре]
этап: проверка
сейчас: проверить сделанное
ожидается: вердикт
инструкция: проверь сделанное сразу, а не обещай проверить, и назови вердикт
            первой строкой; нашёл проблемы —
            вызови update_stage(stage="execution"), не нашёл — update_stage(stage="done")
цель: приложение доставки под iOS
ограничение: релиз до конца мая
[конец фактов о разговоре]
```

И этап, и записи — про одну и ту же текущую задачу, оба живут в чате
и умирают с ним. Второй блок на ту же тему был бы тем самым лишним
разделением промпта, про которое говорит лекция: всё в одном промпте.

Этап стоит **первой строкой и всегда**, пока блок есть, — где задача, модель
угадывать не должна. За ним то, что этап **значит**: чем заняты, чего ждут
и что на нём велено. Пустые строки в блок не едут: «ожидается: » заняло бы
место, ничего не сказав, — и у «готова» ни ожидания, ни инструкции нет вовсе.

**Пустой чат блока не заводит вовсе.** Этап есть у задачи всегда, но
умолчание само по себе не новость: чат стоит на планировании ровно потому,
что его завели. Блок появляется от уведённого с умолчания этапа, заполненного
поля или записи о задаче — и это одно условие, а не три.

### Пауза и продолжение достались даром — но проверены, а не предположены

Состояние лежит в своей таблице и поднимается в конструкторе агента вместе
с историей, сводками и рабочей памятью. Закрыли ноутбук на этапе «проверка» —
открыли и продолжили с «проверки»: полоса показывает тот же этап, в промпт
уезжает тот же блок, объяснять заново нечего.

Проверка на это смотрит буквально: настоящее переоткрытие файла базы
и подъём чата из него.

## Что видно на экране

**Полоса этапов — в шапке чата, и вкладки под неё больше нет вовсе.** Она
в кадре постоянно: панель сворачивается, и этап, спрятанный туда, на экране
не стоял бы почти никогда.

```
○ планирование  ──▶  ● работа  ──▶  ○ проверка  ──▶  ○ готово
                                        ↑ достижимо        ↑ приглушено
```

Текущий выделен, **достижимые по карте видны обычными, недостижимые
приглушены**: раз нажатием этап не меняется, полоса обязана говорить, куда
можно, — и запрет виден до того, как его попытались нарушить. Карту
называет сервер полем `moves`: вторая её копия на клиенте разошлась бы
с первой молча.

На планировании рядом стоит кнопка **«Утвердить план»** — и только тогда,
когда в чате есть хотя бы один ответ модели: утверждать нечего, пока плана
не предложили. Она **сама отправляет обмен** («План утверждён. Выполни первый
шаг плана прямо сейчас и покажи результат работы, а не намерение её
начать.»), чтобы агент не отвечал согласием вместо дела.

Под полосой — то, что уедет в блок задачи: «сейчас: … · ожидается: … ·
инструкция: …». Строки собирает сервер, а не клиент: под полосой обязано
стоять ровно то, что **видит модель**. Два поля из трёх правятся щелчком
прямо там, тем же приёмом, каким правятся записи памяти: поле встаёт
на место строки, Enter и уход фокуса сохраняют, Escape отменяет. Инструкция
этапа не правится — она про то, как вести себя на этапе, а не про эту задачу.

Журнал переходов — там же, свёрнутой строкой «переходов: 3», раскрытие
по клику:

```
работа → проверка        агент                14:05
проверка → готово        агент    отклонено   14:07
```

**Отклонённые попытки стоят в нём наравне с удавшимися.** Это доказательство,
что автомат работает: видно не только что переходы случаются, но и что
запрещённые не случаются.

Ключевой кадр: агент сам уехал в «проверку», а попытавшись закрыть задачу
через голову проверки, получил отказ — и это видно строкой под ответом:

```
переход в «готово» отклонён: сначала проверка
```

Молчать нельзя: модель просила переход, его не дали, и без строки это
выглядело бы так, будто она ничего и не просила.

Блок видно там же, где видно всё остальное, что уехало в модель: кнопка
**«Показать промпт запроса»** под ответом.

## Хранение

Своя таблица `task_state`: `session_id` первичным ключом — у разговора ровно
одна задача, — этап, два поля и время. Таблица, а не поле в конфиге: конфиг
это «чем один чат отличается от другого», а этап — не настройка, а то, где
разговор сейчас находится. Тот же довод, по которому таблицей заведено
родство; `CREATE TABLE IF NOT EXISTS` накатится на живую базу сам.

Строки может не быть вовсе — тогда умолчание: планирование и два пустых поля.

Рядом — `task_log`, журнал этапа: строка на каждый переход, чей он (человека
или агента) и состоялся ли (`ok`). Состояние — это где задача **сейчас**,
журнал — как она сюда пришла. Метрик в нём больше нет: этап двигает
инструмент внутри самого обмена, отдельного обращения к модели у него
не бывает, и платить за переход нечем. Колонку снимает миграция, `ok`
добавляет — база у пользователя живая, и «удалите файл» здесь не ответ.

Журнал чистится вместе с состоянием, одним методом и на тех же трёх путях.
**Ветка его не уносит**: состояние у неё то же, а летопись своя — переходы
случились в разговоре родителя.

Чистится состояние на **всех трёх** путях — `/забыть`, удаление чата,
служебная очистка базы: каскада в схеме нет, а зажима по длине истории
у блока задачи нет тем более. Забытый разговор, оставивший «этап: проверка»,
врал бы следующему первой же строкой.

**Ветвление уносит состояние целиком** — по тому же правилу, что рабочую
память: этап не заменяет собой ни одной реплики, а задача у ветки та же.
Границы по точке ветвления у него поэтому нет.

## API

| Ручка | Что делает |
|---|---|
| `PATCH /api/agents/{id}/task` | «сейчас» и «ожидается»; этапа здесь нет — `stage` лишнее поле, 400 |
| `POST /api/agents/{id}/task/approve` | «Утвердить план»: планирование → работа; не оттуда — 409 |
| `GET /api/profile`, `PATCH /api/profile` | профиль: как отвечать этому человеку |
| `GET /api/agents/{id}/memory` | три слоя памяти разом |
| `GET/POST /api/memory`, `PATCH/DELETE /api/memory/{seq}` | долговременный слой |
| `GET/POST /api/agents/{id}/working`, `PATCH/DELETE /api/agents/{id}/working/{seq}` | рабочий слой, в области чата |
| `PATCH /api/agents/{id}` | конфиг чата, включая `strategy` |
| `POST /api/agents/{id}/messages`, `/regenerate`, `/cancel`, `/fork` | обмен потоком SSE, перегенерация, отмена, ветка |
| `GET /api/agents`, `POST /api/agents`, `GET/DELETE /api/agents/{id}` | список, создание, чат целиком, удаление |
| `GET /api/models`, `GET /api/health` | каталог моделей; ключ, реестр, число чатов |

Отдельного `GET` у состояния нет намеренно — оно приезжает **с самим чатом**
вместе с журналом, потому что полоса стоит в шапке и рисуется тем же ответом,
что и лента; второй источник того же числа разошёлся бы с первым.

Тело разбирают те же общие помощники, что у профиля и памяти: лишнее поле —
400, пустое тело правки — 400.

## Проверки

Живых вызовов к LLM нет — поток подменяется заглушкой.

```bash
.venv/bin/python checks/run_checks.py    # 32 проверки, включая три ниже и клиентскую
.venv/bin/python checks/restart.py       # два процесса подряд на одном файле
.venv/bin/python checks/two_processes.py # сервер и консоль на одной базе
.venv/bin/python checks/spawn_100.py     # сто агентов в одном процессе
node checks/browser_check.js             # клиент под node, 299 утверждений
```

Бьют по поведению, а не по исходнику: `browser_check.js` исполняет настоящий
`app/static/app.js` под node на стенде с минимальным DOM и сервером
с настоящими кадрами SSE. Греп по клиенту проверкой клиента не считается.

Механизм новый, а живьём проверить его нечем — ключа нет. Поэтому **заглушка
научилась изображать вызов инструмента**: отдаёт поток с вызовом, а следом
поток с продолжением. Видит она при этом ровно то, что видела бы модель, —
и промпт, и объявление, — поэтому сцена «зову, когда инструмент объявлен»
пишется честно, и так же честно пишется сцена «упрямая модель зовёт
необъявленный».

Проверок стало 32: про инструмент заведена своя, про состояние задачи
осталась прежняя.

Про состояние: этап первой строкой блока и его инструкция следом; набранное
руками, побеждающее зашитое; пустой чат без блока вовсе и с пустым слотом
врезки; кнопка «Утвердить план» единственным переходом человека, а второе
нажатие — 409; `stage`, не принятый правкой текста, — 400; запрещённый
переход, отбитый и записанный в журнал отклонённым, а «тот же этап»
и незнакомый — не записанные вовсе; и то, ради чего день затеян, — **пауза
и продолжение**: закрытый и заново открытый файл базы отдаёт тот же этап,
тот же шаг, тот же блок в промпте и весь журнал. Ветка уносит состояние
целиком.

Про инструмент — своя проверка, и в ней всё, чего лишиться нельзя:
объявление есть на «работе» и «проверке» и **отсутствует** на планировании
и «готове»; вызов из **настоящего** потока собирается по `index` из шести
кусков двух вызовов, перемешанных между собой, — и это настоящий
`stream_completion` поверх подменённого транспорта, а не заглушка,
изображающая саму себя; разрешённый переход применяется, доезжает до базы
и помечается «агентом»; запрещённый **не применяется** — состояние прежнее,
модель получает довод, журнал строку «отклонено», человек строку под
ответом; из планирования инструмент не выпускает; не позвала, позвала
с кривым аргументом (четыре вида кривизны) и позвала тем же этапом —
не произошло ничего; предел удержал обмен на трёх обращениях и снял
объявление на последнем; метрики обоих оборотов сложились в итог по чату,
а число сообщений не выросло.

На стенде клиента проверено то, что снимают на видео: полоса показывает этап
**открытого чата**, а не умолчание; нажатие на неё **не шлёт ничего**
и этап не двигает; недостижимые по карте этапы приглушены; вкладки «Задача»
нет ни кнопкой, ни страницей, ни именем в списке страниц панели; «сейчас»
и «ожидается» правятся щелчком под полосой, а инструкция этапа не правится;
кнопки «Утвердить план» нет в чате без ответа модели, а нажатая — идёт своей
ручкой и **сама отправляет обмен**; полоса переезжает **сразу после ответа**,
журнал разворачивается из строки «переходов: 1», а запрещённый переход виден
трижды — полосой, строкой «отклонено» в журнале и строкой отказа под ответом.

Стенд при этом **не щедрее сервера**: карта переходов у него своя копия,
но отказывает она там же, и `stage` в правке текста он не принимает так же,
как не принимает сервер. Стенд, принимающий то, чего не принимает сервер,
за три недели трижды прятал настоящую дыру.

Таблица очистки прежняя: слоёв шесть, клеток восемнадцать, тринадцать
уносят, пять **оставляют**. Обратная половина таблицы такая же обязательная,
как прямая.

Зелёный прогон сам по себе ничего не доказывает, поэтому по каждому новому
утверждению прогнана мутация в одну строку, от которой оно краснеет.
Полный список — в отчёте дня; коротко: объявление инструмента везде и нигде;
`tools`, не уехавшие в тело; аргументы, присвоенные вместо дописывания,
и вызовы, слипшиеся в один по индексу; цикл, не пошедший за продолжением,
и предел, снятый совсем; планирование, из которого инструмент выпускает;
отказ, о котором промолчали; карта, потерявшая обратное ребро; журнал без
отклонённых; метрики второго оборота, потерянные в итоге; `stage`, принятый
правкой текста; полоса, где достижимо всё; кнопка плана в пустом чате
и кнопка, не отправившая обмен; вкладка «Задача», вернувшаяся в список
страниц; строка отказа, не нарисованная под ответом; журнал, схлопнутый
наоборот.

## Как запустить

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000. В шапке чата — полоса этапов. Попросите
план, дождитесь ответа и нажмите **«Утвердить план»**: задача уедет в работу,
а обмен отправится сам. Скажите, что работа сделана, — модель вызовет
`update_stage`, и полоса переедет на «проверку» сразу после ответа; под
полосой появится строка «переходов: 1». Нажмите **«Показать промпт запроса»**
— блок `[факты о разговоре]` начинается строкой «этап: …», а следом стоит
инструкция с поводом звать инструмент. Перезапустите сервер и откройте чат
снова: этап, шаг и журнал на месте.
