# День 34. Ассистент для работы с файлами проекта

Консольный ассистент для произвольного проекта: задайте цель обычной фразой,
модель сама вызывает `list/search/read/create/edit/diff` через стандартные
Chat Completions `tool_calls`. Видны вызовы и результаты инструментов.
Изменения сначала попадают в приватный черновик вне проекта; `/diff` показывает
предложение, `/apply` человека сохраняет его.

## Запуск

Python >=3.11, совместимый HTTP endpoint с `/models`, Chat Completions и tools.

```sh
make setup
# Или: make setup PYTHON=/path/to/python
make check
make run PROJECT=/absolute/path/to/project
# Эквивалент:
.venv/bin/python -m file_agent --project /absolute/path/to/project
```

В CLI выполните `/settings`: задайте URL, при необходимости ключ через скрытый
getpass и явно выберите chat model из каталога. ID изначально пустой, автоматического
выбора нет. Пустой ключ сохраняет прежний, `-` удаляет. Reasoning по умолчанию OFF,
`temperature=0.2`, `max_tokens=1024`. Температура конечная неотрицательная,
max_tokens положительное целое или `null` (поле не отправляется); верхних caps нет.
Поддержку параметров и tools определяет сервер модели. System HTTP proxy сохранён,
localhost идёт напрямую; live inference при разработке не выполнялся.

## Два воспроизводимых сценария

Выберите собственный безопасный проект с реализацией, её вызывающим кодом и документацией.

1. Попросите найти использования интересующего вас API во всём проекте и составить
   отчёт с путями и строками. Ассистент выбирает файлы и поисковые запросы сам.
2. Попросите обновить или создать документацию на основании реализации и вызывающего
   кода. Посмотрите tool trace и `/diff`, затем явно выполните `/apply` либо `/discard`.

Запросы свободные: специальных шаблонов команд и встроенного корпуса нет.
Чтобы повторить работу, верните выбранный проект в исходное состояние вручную,
выполните `/new` и поставьте ту же цель. Ответ живой модели может отличаться;
`make check` воспроизводит оба сценария с нейтральным HTTP mock без inference.

Команды: `/settings`, `/models`, `/status`, `/diff`, `/apply`, `/discard`, `/new`,
`/help`, `/exit`. `/new` требует сначала разрешить pending edits. Выход сохраняет
черновик; следующий запуск с тем же state его восстанавливает. Ctrl-C во время
обмена прекращает цикл и помечает черновик incomplete: завершите успешную цель
или выполните `/discard`, прежде чем применять его. Автоматического apply нет.

Настройки и черновик (0600) по умолчанию находятся в
`~/.local/state/file-assistant/<hash-absolute-project-path>/`; `--state /private/path`
задаёт другой каталог вне проекта. Ключи, содержимое черновика и реальные проекты
не коммитьте. История последних трёх успешных пар хранится только в памяти.

Файловые инструменты ограничены UTF-8 текстом, безопасными относительными путями
и явными лимитами. Root `AGENTS.md` читается как ограниченные правила проекта.
Перед записью проверяются все исходные SHA256 и коллизии новых файлов; конфликт
останавливает apply. Replace атомарен для одного файла, общей транзакции нескольких
файлов нет. Фильтры не распознают любой секрет в обычном коде: выбирайте допустимый
проект. Подробные границы, лимиты и проверяемое поведение — в
[архитектуре](docs/architecture.md).

## Задание

```text
🔥 День 34. Ассистент для работы с файлами проекта

Сделайте ассистента, который активно работает с файлами, а не просто отвечает текстом.

Через MCP или доступный вам tooling ассистент должен уметь:

👉 читать файлы проекта
👉 искать информацию по нескольким файлам
👉 анализировать содержимое
👉 создавать или изменять файлы

Примеры сценариев (реализуйте минимум 2):

👉 найти все места, где используется определённый компонент / API
👉 обновить документацию на основе изменений в коде
👉 сгенерировать новый файл (README / ADR / changelog)
👉 проверить соответствие файлов правилам или инвариантам
👉 подготовить diff или список изменений

Важно:

👉 ассистент сам инициирует работу с файлами
👉 вы задаёте задачу на уровне цели, а не “открой файл X”

Минимальный результат:

👉 ассистент работает минимум с 2–3 файлами
👉 изменения сохраняются или выводятся как diff
👉 результат можно воспроизвести повторно

Результат:

AI-ассистент, который выполняет реальные операции с файлами проекта
```
